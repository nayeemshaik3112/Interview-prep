# TOPIC 1 — map()

## Concept
`map()` transforms each element from one form to another. It takes a `Function<T, R>` — input type T, output type R. Think of it as SQL's SELECT — picking/transforming specific columns.

## Interviewer Expectation
"Can this developer extract and transform data fluently?"

## Syntax
```java
stream.map(e -> e.getFirstName())          // lambda
stream.map(Employee::getFirstName)         // method reference (preferred)
stream.map(e -> e.getSalary() * 1.10)      // transformation
```

## Examples

### Easy: Extract all employee first names
```java
List<String> names = employees.stream()
    .map(Employee::getFirstName)
    .collect(Collectors.toList());
// [Amit, Priya, Rahul, Sneha, Vikram, ...]
```

### Medium: Get full names of employees earning above 70,000
```java
List<String> highEarners = employees.stream()
    .filter(e -> e.getSalary() > 70000)
    .map(Employee::getFullName)
    .collect(Collectors.toList());
// [Priya Verma, Vikram Singh, Rajesh Pillai, ...]
```

### Interview-Level: Create a salary hike map — 10% hike for everyone, return Map<String, Double>
```java
Map<String, Double> hikedSalaries = employees.stream()
    .collect(Collectors.toMap(
        Employee::getFullName,
        e -> e.getSalary() * 1.10
    ));
```

## Stream Flow (Medium example)
```
[35 employees] → filter(salary > 70000) → [~10 employees] → map(getFullName) → [10 Strings] → collect → List<String>
```

## Common Mistakes
- Using `map()` when you need `flatMap()` (for nested collections like List<List<String>>)
- Forgetting that `map()` changes the stream type — `Stream<Employee>` becomes `Stream<String>` after `map(Employee::getName)`
- Trying to use `map()` for side effects (use `forEach()` instead)

## Follow-Up Questions
1. **"Difference between map() and flatMap()?"** → map does 1-to-1 transformation, flatMap flattens nested structures
2. **"Can map() return null?"** → Yes, but downstream operations may NPE. Always be careful.
3. **"map() vs peek()?"** → map transforms and returns new value; peek is for side-effects and returns the same element

---------------------------------------------------------------------------------------------------------------

# TOPIC 2 — flatMap()

## Concept
`flatMap()` is used when each element maps to a collection/stream, and you want to flatten all those into a single stream. It takes a `Function<T, Stream<R>>`.

Think: Employee has `List<String> skills`. If you use `map()`, you get `Stream<List<String>>`. With `flatMap()`, you get `Stream<String>`.

## Interviewer Expectation
This is a **medium-hard** question. Interviewers ask this to separate experienced developers from beginners.

## Syntax
```java
stream.flatMap(e -> e.getSkills().stream())     // flatten nested list
stream.flatMap(Collection::stream)               // method reference on collection
```

## Examples

### Easy: Get all unique skills across all employees
```java
List<String> allSkills = employees.stream()
    .filter(e -> e.getSkills() != null)          // null-safety! Employee #23 has null skills
    .flatMap(e -> e.getSkills().stream())
    .distinct()
    .collect(Collectors.toList());
// [Java, Spring Boot, MySQL, Kafka, Docker, Kubernetes, ...]
```

### Medium: Find employees who know "Kafka"
```java
List<String> kafkaDevs = employees.stream()
    .filter(e -> e.getSkills() != null)
    .filter(e -> e.getSkills().contains("Kafka"))
    .map(Employee::getFullName)
    .collect(Collectors.toList());
// [Priya Verma, Vikram Singh, Karthik Rajan, Manoj Tiwari, Arun Prasad, Anjali Chopra]
```

### Interview-Level: Count frequency of each skill across the organization
```java
Map<String, Long> skillFrequency = employees.stream()
    .filter(e -> e.getSkills() != null)
    .flatMap(e -> e.getSkills().stream())
    .collect(Collectors.groupingBy(
        Function.identity(),
        Collectors.     ()
    ));
// {Java=20, Spring Boot=8, Docker=9, AWS=6, Kafka=6, MySQL=5, ...}
```

## Common Mistakes
- **Forgetting null-safety:** Employee #23 has `skills = null`. Calling `.stream()` on null = NPE.
- **Using map() instead of flatMap():** `map(e -> e.getSkills())` gives `Stream<List<String>>` — you can't call `distinct()` or `count()` on individual skills.
- **Forgetting `.stream()`:** `flatMap(e -> e.getSkills())` doesn't compile. You need `flatMap(e -> e.getSkills().stream())`.

## Follow-Up Questions
1. **"When would you use flatMap in a real backend project?"** → Flattening nested DTOs, combining results from multiple API calls, parsing CSV rows with multiple comma-separated values.
2. **"map() vs flatMap() — give a one-line difference."** → map is 1-to-1 (one input → one output), flatMap is 1-to-many (one input → zero or more outputs, flattened).

---------------------------------------------------------------------------------------------------------------

# TOPIC 3 — sorted() + Comparator

## Concept
`sorted()` is an intermediate operation that sorts stream elements. Without arguments, it uses natural ordering. With a `Comparator`, it sorts by custom rules.

## Interviewer Expectation
Sorting + Comparator is asked in 80%+ interviews. Interviewers specifically test: natural sort, reverse sort, multi-field sort, and Comparator chaining.

## Syntax
```java
stream.sorted()                                           // natural order (for Comparable types)
stream.sorted(Comparator.comparing(Employee::getSalary))  // ascending by salary
stream.sorted(Comparator.comparing(Employee::getSalary).reversed())  // descending
stream.sorted(Comparator.comparing(Employee::getDepartment)
    .thenComparing(Employee::getSalary))                  // multi-field sort
```

## Examples

### Easy: Sort employees by salary ascending
```java
List<Employee> sorted = employees.stream()
    .sorted(Comparator.comparing(Employee::getSalary))
    .collect(Collectors.toList());
```

### Medium: Sort by department, then by salary descending within each department
```java
List<Employee> sorted = employees.stream()
    .filter(e -> e.getDepartment() != null)
    .sorted(Comparator.comparing(Employee::getDepartment)
        .thenComparing(Comparator.comparing(Employee::getSalary).reversed()))
    .collect(Collectors.toList());
```

### Interview-Level: Find the top 3 highest-paid employees
```java
List<Employee> top3 = employees.stream()
    .sorted(Comparator.comparing(Employee::getSalary).reversed())
    .limit(3)
    .collect(Collectors.toList());
// [Suresh Menon(120000), Arun Prasad(115000), Vikram Singh/Manoj Tiwari/Aditya Narayan(95000)]
```

### Interview-Level: Sort by age, if age is same then by firstName
```java
List<Employee> sorted = employees.stream()
    .sorted(Comparator.comparingInt(Employee::getAge)
        .thenComparing(Employee::getFirstName))
    .collect(Collectors.toList());
```

## Common Mistakes
- **Forgetting `.reversed()` for descending:** Just `Comparator.comparing(Employee::getSalary)` is ascending.
- **Using `comparingInt` vs `comparing`:** For primitive int/double, `comparingInt()` and `comparingDouble()` avoid boxing overhead. Use them.
- **Null-handling in sorted fields:** If department is null, `Comparator.comparing(Employee::getDepartment)` throws NPE. Fix: `Comparator.comparing(Employee::getDepartment, Comparator.nullsLast(Comparator.naturalOrder()))`.

## Follow-Up Questions
1. **"Is sorted() a stateful operation?"** → Yes. It must see all elements before producing output (unlike filter which is stateless).
2. **"sorted() vs List.sort()?"** → `sorted()` returns a new sorted stream without modifying the source. `List.sort()` sorts the list in-place.
3. **"What is Comparator.naturalOrder()?"** → Returns a comparator that sorts Comparable objects in their natural order (alphabetical for strings, numerical for numbers).

# TOPIC 4 — distinct()

## Concept
`distinct()` removes duplicate elements from a stream. It uses `equals()` and `hashCode()` to determine duplicates.

## Interviewer Expectation
Simple concept, but interviewers test: do you know it uses equals/hashCode? What about custom objects?

## Examples

### Easy: Get distinct salaries
```java
List<Double> uniqueSalaries = employees.stream()
    .map(Employee::getSalary)
    .distinct()
    .collect(Collectors.toList());
```

### Medium: Get distinct departments (null-safe)
```java
List<String> departments = employees.stream()
    .map(Employee::getDepartment)
    .filter(Objects::nonNull)
    .distinct()
    .collect(Collectors.toList());
// [Engineering, HR, DevOps, QA, Finance]
```

### Interview-Level: Find duplicate first names
```java
Map<String, Long> nameCount = employees.stream()
    .collect(Collectors.groupingBy(Employee::getFirstName, Collectors.counting()));

List<String> duplicateNames = nameCount.entrySet().stream()
    .filter(e -> e.getValue() > 1)
    .map(Map.Entry::getKey)
    .collect(Collectors.toList());
// [Amit, Priya]
```

## Common Mistakes
- **distinct() on custom objects without overriding equals/hashCode:** By default, it uses Object reference equality. Two Employee objects with same data but different references won't be considered duplicates unless you override equals() and hashCode().
- **Assuming distinct() maintains order:** With sequential streams, order is maintained. With parallel streams, no guarantee.

## Follow-Up
1. **"Is distinct() stateful or stateless?"** → Stateful — it must remember previously seen elements.
2. **"How does distinct() handle nulls?"** → It treats null as a valid value. Multiple nulls are reduced to one.

# TOPIC 5 — collect() and Collectors

## Concept
`collect()` is a terminal operation that transforms a stream into a concrete result — a List, Set, Map, String, or a custom accumulation. It takes a `Collector`.

## This is the MOST IMPORTANT terminal operation. 80% of stream chains end with collect().

---------------------------------------------------------------------------------------------------------------

## 5a — Collectors.toList() and Collectors.toSet()

```java
// toList — preserves insertion order, allows duplicates
List<String> names = employees.stream()
    .map(Employee::getFirstName)
    .collect(Collectors.toList());

// toSet — no duplicates, no guaranteed order
Set<String> uniqueNames = employees.stream()
    .map(Employee::getFirstName)
    .collect(Collectors.toSet());

// toUnmodifiableList (Java 10+, but interviewers like to ask)
List<String> immutable = employees.stream()
    .map(Employee::getFirstName)
    .collect(Collectors.toUnmodifiableList());
```

### Follow-Up: "What type of List does toList() return?"
→ It returns an ArrayList. It's mutable. If you need an immutable list, use `toUnmodifiableList()` or wrap with `Collections.unmodifiableList()`.

---------------------------------------------------------------------------------------------------------------

## 5b — Collectors.toMap()

### Easy: Map of employee name → salary
```java
Map<String, Double> nameSalary = employees.stream()
    .collect(Collectors.toMap(
        Employee::getFullName,
        Employee::getSalary
```

### Interview Trap: Duplicate keys throw IllegalStateException!
If two employees have the same full name (they don't in our dataset, but interviewers test this), toMap crashes. Fix:

```java
Map<String, Double> nameSalary = employees.stream()
    .collect(Collectors.toMap(
        Employee::getFirstName,       // "Amit" appears twice!
        Employee::getSalary,
        (existing, replacement) -> existing   // merge function: keep first
    ));
```

### Interview-Level: Map of department → list of employee names
```java
Map<String, List<String>> deptNames = employees.stream()
    .filter(e -> e.getDepartment() != null)
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.mapping(Employee::getFullName, Collectors.toList())
```

## Common Mistakes with toMap()
- **Not providing merge function when keys can duplicate** → This is the #1 interview trap
- **Null values:** toMap throws NPE if the value mapper returns null. Use a conditional or filter out nulls first.

```java
        e -> e.getSalary() >= 60000,
        Collectors.counting()
    ));
// {true=15, false=20}
```

### Interview-Level: Partition by experience (joined before/after 2021), get names
```java
Map<Boolean, List<String>> byExperience = employees.stream()
    .collect(Collectors.partitioningBy(
        e -> e.getJoiningDate().isBefore(LocalDate.of(2021, 1, 1)),
        Collectors.mapping(Employee::getFullName, Collectors.toList())
    ));
// true = senior employees, false = junior employees
```

## Follow-Up
**"groupingBy vs partitioningBy?"**
→ partitioningBy always returns both keys (true and false), even if one group is empty. groupingBy only returns keys that have at least one element. partitioningBy takes a Predicate; groupingBy takes a Function.

## 5e — Collectors.counting()

Already seen above inside groupingBy. Can also be used standalone:

```java
long totalEngineers = employees.stream()
```

## 5g — Collectors.summarizingDouble/Int/Long()

Returns a summary with count, sum, min, average, max — all at once.

### Interview-Level: Full salary statistics per department

```java
Map<String, DoubleSummaryStatistics> stats = employees.stream()
```

# TOPIC 6 — max(), min(), and Optional

## Concept
`max()` and `min()` are terminal operations that return `Optional<T>`. They take a Comparator.

`Optional` is a container that may or may not hold a value. It forces you to handle the "no result" case.

## Interviewer Expectation
Interviewers test two things: (1) Can you find max/min correctly? (2) Do you handle Optional properly (not calling `.get()` blindly)?

## Examples

### Easy: Find highest salary
```java
Optional<Employee> highest = employees.stream()
    .max(Comparator.comparingDouble(Employee::getSalary));
highest.ifPresent(e -> System.out.println(e.getFullName() + " : " + e.getSalary()));
// Suresh Menon : 120000.0
```

### Medium: Find youngest employee in Engineering
```java
Optional<Employee> youngest = employees.stream()
    .filter(e -> "Engineering".equals(e.getDepartment()))
    .min(Comparator.comparingInt(Employee::getAge));
youngest.ifPresent(e -> System.out.println(e.getFullName() + " age " + e.getAge()));
// Swathi Rao age 24
```

### Interview-Level: Find the second highest salary in the entire company
```java
Optional<Double> secondHighest = employees.stream()
    .map(Employee::getSalary)
    .distinct()                // remove duplicate salary values (95000 appears 3 times)
    .sorted(Comparator.reverseOrder())
    .skip(1)
    .findFirst();
secondHighest.ifPresent(s -> System.out.println("Second highest: " + s));
// Second highest: 115000.0
```

## Optional — Key Methods Interviewers Test
```java
Optional<Employee> opt = employees.stream().findFirst();

opt.isPresent()            // returns boolean
opt.get()                  // DANGEROUS — throws NoSuchElementException if empty
opt.orElse(defaultValue)   // return default if empty
opt.orElseGet(Supplier)    // lazily compute default
opt.orElseThrow()          // throw exception if empty
opt.ifPresent(Consumer)    // execute only if value exists
opt.map(Function)          // transform value inside Optional
opt.filter(Predicate)      // filter value inside Optional
opt.flatMap(Function)      // flatten nested Optional
```

## Common Mistakes
- **Calling `.get()` without checking:** This is the #1 mistake interviewers look for. Use `orElse()` or `ifPresent()`.
- **Using `orElse()` with expensive operation:** `orElse(expensiveCall())` always executes the argument. Use `orElseGet(() -> expensiveCall())` for lazy evaluation.

## Follow-Up
1. **"How do you create an Optional?"** → `Optional.of(value)` (NPE if null), `Optional.ofNullable(value)` (safe), `Optional.empty()`
2. **"Optional in method return types — good or bad?"** → Good for return types, bad for method parameters and fields.

# TOPIC 7 — reduce()

## Concept
`reduce()` combines all elements into a single result by repeatedly applying a binary operation. Think of it as SQL SUM/MAX/CONCAT but generalized.

## Syntax
```java
reduce(identity, BinaryOperator)     // with identity/seed value — returns T
reduce(BinaryOperator)               // without identity — returns Optional<T>
```

## Examples

### Easy: Sum of all salaries
```java
double totalSalary = employees.stream()
    .map(Employee::getSalary)
    .reduce(0.0, Double::sum);
// Or simpler: .mapToDouble(Employee::getSalary).sum()
```

### Medium: Find employee with the longest name
```java
Optional<Employee> longestName = employees.stream()
    .reduce((e1, e2) ->
        e1.getFullName().length() >= e2.getFullName().length() ? e1 : e2
    );
```

### Interview-Level: Concatenate all department names with comma (without Collectors.joining)
```java
String allDepts = employees.stream()
    .map(Employee::getDepartment)
    .filter(Objects::nonNull)
    .distinct()
    .reduce((a, b) -> a + ", " + b)
    .orElse("");
// "Engineering, HR, DevOps, QA, Finance"
```

## Stream Flow (sum example)
```
[55000, 75000, 35000, 42000, ...]
reduce(0.0, Double::sum)

Step 1: 0.0 + 55000 = 55000
Step 2: 55000 + 75000 = 130000
Step 3: 130000 + 35000 = 165000
... continues until all elements are processed
Final result: total sum
```

## Common Mistakes
- **Using reduce for complex aggregations:** If you need count + sum + average, use `summarizing` collectors instead.
- **Mutating an accumulator:** The identity value should be immutable. Don't use a mutable list as identity with `reduce`.

## Follow-Up
1. **"reduce() with identity vs without — what's the difference?"** → With identity returns T directly. Without identity returns Optional<T> because stream might be empty.
2. **"When to use reduce vs collect?"** → reduce for immutable accumulations (sum, max, concat). collect for mutable accumulations (building lists, maps).

# TOPIC 8 — findFirst() and findAny()

## Concept
Both return `Optional<T>`. `findFirst()` returns the first element in encounter order. `findAny()` returns any element (optimized for parallel streams).

## Examples

### Easy: Find any employee from Mumbai
```java
Optional<Employee> mumbaiEmp = employees.stream()
    .filter(e -> "Mumbai".equals(e.getCity()))
    .findFirst();
mumbaiEmp.ifPresent(System.out::println);
```

### Medium: Find the first employee who joined before 2018
```java
Optional<Employee> senior = employees.stream()
    .filter(e -> e.getJoiningDate().isBefore(LocalDate.of(2018, 1, 1)))
    .findFirst();
// Suresh Menon (joined 2015) or Sanjay Dubey (joined 2016) depending on list order
```

### Interview-Level: Find the first employee in each department (ordered by joining date)
```java
Map<String, Employee> firstJoiners = employees.stream()
    .filter(e -> e.getDepartment() != null)
    .sorted(Comparator.comparing(Employee::getJoiningDate))
    .collect(Collectors.toMap(
        Employee::getDepartment,
        Function.identity(),
        (existing, replacement) -> existing  // keep the first one encountered
    ));
```

## Follow-Up
**"findFirst() vs findAny()?"**
→ In sequential streams, both return the same element. In parallel streams, `findAny()` is faster because it doesn't need to respect encounter order. Use `findFirst()` when order matters, `findAny()` when you just need any match.

# TOPIC 9 — anyMatch(), allMatch(), noneMatch()

## Concept
Short-circuit terminal operations that return `boolean`.
- `anyMatch(predicate)` — true if ANY element matches
- `allMatch(predicate)` — true if ALL elements match
- `noneMatch(predicate)` — true if NO element matches

## Examples

### Easy: Is there any employee from Chennai?
```java
boolean hasChennaite = employees.stream()
    .anyMatch(e -> "Chennai".equals(e.getCity()));
// true
```

### Medium: Are all employees active?
```java
boolean allActive = employees.stream()
    .allMatch(Employee::isActive);
// false (4 are inactive)
```

### Medium: Does no employee earn above 150,000?
```java
boolean noneAbove150k = employees.stream()
    .noneMatch(e -> e.getSalary() > 150000);
// true
```

### Interview-Level: Does every department have at least one employee with rating >= 4.5?
```java
Map<String, Boolean> deptHasTopPerformer = employees.stream()
    .filter(e -> e.getDepartment() != null)
    .collect(Collectors.groupingBy(Employee::getDepartment))
    .entrySet().stream()
    .collect(Collectors.toMap(
        Map.Entry::getKey,
        e -> e.getValue().stream().anyMatch(emp -> emp.getRating() >= 4.5)
    ));
```

## Common Mistakes
- **Confusing allMatch on empty streams:** `allMatch` returns `true` for an empty stream (vacuous truth). This trips many candidates.
- **Confusing noneMatch with !anyMatch:** They are logically equivalent, but `noneMatch` reads cleaner.

## Follow-Up
**"Are these short-circuit operations?"** → Yes. `anyMatch` stops as soon as it finds one match. `allMatch` stops as soon as it finds one non-match. They don't process the entire stream.

# TOPIC 10 — skip() and limit()

## Concept
- `skip(n)` — skips first n elements
- `limit(n)` — takes only first n elements

Together they enable pagination and "nth element" patterns.

## Examples

### Easy: Get first 5 employees
```java
List<Employee> first5 = employees.stream()
    .limit(5)
    .collect(Collectors.toList());
```

### Medium: Pagination — get page 2 (employees 6-10)
```java
int pageSize = 5;
int pageNumber = 2;

List<Employee> page2 = employees.stream()
    .skip((pageNumber - 1) * pageSize)   // skip 5
    .limit(pageSize)                      // take 5
    .collect(Collectors.toList());
```

### Interview-Level: Find the 3rd highest salary
```java
Optional<Double> thirdHighest = employees.stream()
    .map(Employee::getSalary)
    .distinct()
    .sorted(Comparator.reverseOrder())
    .skip(2)
    .findFirst();
// 95000.0
```

### Interview-Level: Find employees ranked 4th to 6th by salary
```java
List<Employee> ranked4to6 = employees.stream()
    .sorted(Comparator.comparingDouble(Employee::getSalary).reversed())
    .skip(3)
    .limit(3)
    .collect(Collectors.toList());
```

## Common Mistakes
- **Order of skip and limit matters:** `skip(2).limit(3)` gives elements 3, 4, 5. `limit(3).skip(2)` gives only element 3.
- **Using skip/limit for second highest without distinct():** If highest salary appears 3 times, skip(1) gives the same salary again.

# TOPIC 11 — peek()

## Concept
`peek()` is an intermediate operation used for debugging/logging. It takes a `Consumer`, performs a side effect, and returns the same stream unchanged.

## Backend Usage
```java
List<Employee> result = employees.stream()
    .filter(e -> e.getSalary() > 80000)
    .peek(e -> log.info("High earner found: {}", e.getFullName()))  // logging
    .map(Employee::getFullName)
    .collect(Collectors.toList());
```

## Interview Trap
**"What's the difference between peek() and map()?"**
→ `peek()` returns the same element (Consumer, no return value). `map()` returns a transformed element (Function, with return value). peek is for side-effects, map is for transformation.

**"Can peek() modify objects?"**
→ Technically yes (if you call setters), but this is bad practice. Streams should be side-effect-free. peek should only be used for debugging/logging.

**"Does peek() always execute?"**
→ No! peek is lazy. If there's no terminal operation, peek does nothing. Also, in short-circuit operations, peek may not run for all elements.

# TOPIC 12 — Method References

## Concept
A shorthand for lambdas when the lambda just calls an existing method. Makes code cleaner and more readable. Interviewers expect 3+ years developers to use these naturally.

## 4 Types
```java
// 1. Static method reference
Function<String, Integer> parser = Integer::parseInt;
// equivalent to: s -> Integer.parseInt(s)

// 2. Instance method of a particular object
Consumer<String> printer = System.out::println;
// equivalent to: s -> System.out.println(s)

// 3. Instance method of an arbitrary object of a particular type
Function<Employee, String> getName = Employee::getFirstName;
// equivalent to: e -> e.getFirstName()

// 4. Constructor reference
Supplier<ArrayList> listMaker = ArrayList::new;
// equivalent to: () -> new ArrayList()
```

## Interview Examples on Employee Dataset
```java
// Instead of:
employees.stream().map(e -> e.getFirstName()).collect(Collectors.toList());
// Write:
employees.stream().map(Employee::getFirstName).collect(Collectors.toList());

// Instead of:
employees.stream().filter(e -> e.isActive()).collect(Collectors.toList());
// Write:
employees.stream().filter(Employee::isActive).collect(Collectors.toList());

// Instead of:
employees.stream().sorted(Comparator.comparing(e -> e.getSalary()));
// Write:
employees.stream().sorted(Comparator.comparing(Employee::getSalary));

// Instead of:
employees.stream().forEach(e -> System.out.println(e));
// Write:
employees.stream().forEach(System.out::println);
```

## Follow-Up
**"When can't you use method references?"**
→ When you need to pass additional arguments, or combine logic. Example: `e -> e.getSalary() > 50000` cannot be a method reference because it's not just calling a method, it's comparing the result.

# TOPIC 13 — Lambda Expressions

## Concept
Anonymous functions used to implement functional interfaces. The foundation of Streams.

## Syntax Variations
```java
// Full syntax
(Employee e) -> { return e.getSalary() > 50000; }

// Type inference (most common)
e -> e.getSalary() > 50000

// Multiple parameters
(e1, e2) -> e1.getSalary() - e2.getSalary()

// No parameters
() -> System.out.println("Hello")

// Multiple statements
e -> {
    double hike = e.getSalary() * 0.10;
    return e.getSalary() + hike;
}
```

## Key Functional Interfaces (Interviewers Test These)
```java
Predicate<T>      // T → boolean     | Used in: filter()
Function<T, R>    // T → R           | Used in: map()
Consumer<T>       // T → void        | Used in: forEach(), peek()
Supplier<T>       // () → T          | Used in: orElseGet()
BinaryOperator<T> // (T, T) → T     | Used in: reduce()
UnaryOperator<T>  // T → T          | Used in: map() when same type
BiFunction<T,U,R> // (T, U) → R     | Used in: merge functions
Comparator<T>     // (T, T) → int   | Used in: sorted()
```

## Interview Follow-Up
1. **"Can lambdas access local variables?"** → Yes, but only if they're effectively final (not reassigned after initialization).
2. **"What is a functional interface?"** → An interface with exactly ONE abstract method. Annotated with `@FunctionalInterface`.
3. **"Lambda vs anonymous class?"** → Lambdas are concise, don't create a separate .class file, `this` refers to the enclosing class. Anonymous classes create a .class file, `this` refers to the anonymous class instance.

The real power of Streams is chaining multiple operations together. This is what interviewers test most — can you think in pipelines?

## Interview-Level Examples

### Example 1: Find the department with the highest average salary

```java
Map.Entry<String, Double> topDept = employees.stream()
```

```java
Map<String, String> topRatedByCity = employees.stream()

```

### Example 3: Get a comma-separated string of names of all active engineers sorted by salary descending

```java
String result = employees.stream()
```

# TOPIC 15 — Primitive Streams (mapToInt, mapToDouble, mapToLong)

## Concept
Primitive streams (`IntStream`, `DoubleStream`, `LongStream`) avoid boxing overhead and provide extra methods like `sum()`, `average()`, `range()`.

## When to Use
When you need numeric aggregations — sum, average, min, max, range.

## Examples

### Easy: Total salary expenditure
```java
double totalSalary = employees.stream()
    .mapToDouble(Employee::getSalary)
    .sum();
```

### Medium: Salary statistics (without groupingBy)
```java
DoubleSummaryStatistics stats = employees.stream()
    .mapToDouble(Employee::getSalary)
    .summaryStatistics();

System.out.println("Count: " + stats.getCount());
System.out.println("Sum: " + stats.getSum());
System.out.println("Min: " + stats.getMin());
System.out.println("Max: " + stats.getMax());
System.out.println("Avg: " + stats.getAverage());
```

### IntStream.range() for generating sequences
```java
// Print numbers 1 to 10
IntStream.rangeClosed(1, 10).forEach(System.out::println);

// Check if a string is palindrome using IntStream
String str = "MADAM";
boolean isPalindrome = IntStream.range(0, str.length() / 2)
    .allMatch(i -> str.charAt(i) == str.charAt(str.length() - 1 - i));
```

## Follow-Up
**"mapToInt vs map for getting ages?"**
→ `mapToInt(Employee::getAge)` returns `IntStream` which has `sum()`, `average()` directly. `map(Employee::getAge)` returns `Stream<Integer>` with boxing overhead and no direct sum/average.

**"How to convert IntStream back to Stream<Integer>?"**
→ `intStream.boxed()` converts it to `Stream<Integer>`.

# TOPIC 16 — Parallel Streams (Basics Only)

## Concept
Parallel streams split the stream into chunks and process them on multiple threads using the ForkJoinPool.

## Syntax
```java
employees.parallelStream()          // from collection
employees.stream().parallel()       // convert sequential to parallel
```

## When to Use
- Large datasets (10,000+ elements)
- CPU-intensive operations
- Independent operations (no shared mutable state)

## When NOT to Use (Interviewers Love This Question)
- Small datasets (overhead exceeds benefit)
- I/O operations (threads will block)
- Order-dependent operations
- Operations with shared mutable state (NOT thread-safe)
- Inside a web application (you'd be competing for threads with request handling)

## Example
```java
// Safe: stateless operations
double avgSalary = employees.parallelStream()
    .mapToDouble(Employee::getSalary)
    .average()
    .orElse(0);

// DANGEROUS: modifying shared state
List<String> names = new ArrayList<>();  // NOT thread-safe!
employees.parallelStream()
    .forEach(e -> names.add(e.getFirstName()));  // RACE CONDITION!

// Fix: use collect instead
List<String> names = employees.parallelStream()
    .map(Employee::getFirstName)
    .collect(Collectors.toList());   // thread-safe
```

## Follow-Up
1. **"What thread pool does parallel stream use?"** → Common ForkJoinPool (shared by the entire JVM).
2. **"findFirst() vs findAny() in parallel?"** → findFirst respects order (slower), findAny picks any thread's result (faster).
3. **"Should you use parallel streams in a Spring Boot application?"** → Generally no. Spring Boot already handles concurrency at the request level. Parallel streams inside request handlers compete for threads and can cause thread starvation.

### Q3: Sum of squares of even numbers
```java
int result = numbers.stream()
    .filter(n -> n % 2 == 0)
    .map(n -> n * n)
    .reduce(0, Integer::sum);
```

# TOPIC 19 — COMPLETE Interview Pitfalls & Traps

## Pitfall 1: Stream reuse
```java
Stream<Employee> stream = employees.stream().filter(Employee::isActive);
stream.count();       // works
stream.collect(...);  // THROWS IllegalStateException: stream has already been operated upon
```
Fix: Create a new stream for each terminal operation.

## Pitfall 2: Infinite streams without limit
```java
Stream.iterate(1, n -> n + 1).forEach(System.out::println);  // runs forever!
// Fix:
Stream.iterate(1, n -> n + 1).limit(10).forEach(System.out::println);
```

## Pitfall 3: forEach vs forEachOrdered in parallel streams
```java
employees.parallelStream()
    .forEach(System.out::println);         // output order is random
employees.parallelStream()
    .forEachOrdered(System.out::println);  // output order is maintained
```

## Pitfall 4: Modifying source collection during stream operation
```java
// DANGEROUS:
employees.stream()
    .filter(e -> !e.isActive())
    .forEach(e -> employees.remove(e));  // ConcurrentModificationException!

// Fix: collect first, then remove
List<Employee> inactive = employees.stream()
    .filter(e -> !e.isActive())
    .collect(Collectors.toList());
employees.removeAll(inactive);
```

## Pitfall 5: toMap() with null values
```java
employees.stream()
    .collect(Collectors.toMap(Employee::getFullName, Employee::getCity));
// THROWS NullPointerException if any city is null (Employee #22, #34)!
// Fix: filter nulls or use a workaround
```

## Pitfall 6: groupingBy with null keys
```java
employees.stream()
    .collect(Collectors.groupingBy(Employee::getDepartment));
// Works, but creates a null key in the map for Employee #25
// Most interviewers expect you to filter nulls first
```

## Pitfall 7: sorted() without Comparator on non-Comparable types
```java
employees.stream().sorted();  // ClassCastException! Employee doesn't implement Comparable
// Fix: always provide a Comparator
employees.stream().sorted(Comparator.comparing(Employee::getSalary));
```

## Pitfall 8: Lazy evaluation misunderstanding
```java
// Nothing happens here — no terminal operation!
employees.stream()
    .filter(e -> {
        System.out.println("Filtering: " + e.getFirstName());  // NEVER prints
        return e.isActive();
    })
    .map(Employee::getFullName);
// You MUST end with a terminal operation (collect, forEach, count, etc.)
```

# QUICK REFERENCE — Intermediate vs Terminal Operations

## Intermediate Operations (return Stream, lazy)
| Operation | Purpose | Stateful? |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| filter | Keep matching elements | No |
| map | Transform elements | No |
| flatMap | Flatten nested structures | No |
| sorted | Sort elements | Yes |
| distinct | Remove duplicates | Yes |
| peek | Debug/log side-effects | No |
| skip | Skip first N elements | Yes |
| limit | Take first N elements | Yes |

## Terminal Operations (trigger processing, eager)
| Operation | Returns | Short-circuit? |
|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| collect | Collection/Map/etc | No |
| forEach | void | No |
| count | long | No |
| reduce | Optional<T> or T | No |
| min / max | Optional<T> | No |
| findFirst | Optional<T> | Yes |
| findAny | Optional<T> | Yes |
| anyMatch | boolean | Yes |
| allMatch | boolean | Yes |
| noneMatch | boolean | Yes |
| toArray | T[] | No |

# THE 15 GOLDEN PATTERNS — Memorize These

These 15 patterns cover 95% of all stream interview questions:

```java
// Pattern 1: Filter + Collect
employees.stream().filter(predicate).collect(Collectors.toList());

// Pattern 2: Filter + Map + Collect
employees.stream().filter(pred).map(transform).collect(Collectors.toList());

// Pattern 3: GroupBy + Count
.collect(Collectors.groupingBy(classifier, Collectors.counting()));

// Pattern 4: GroupBy + Average
.collect(Collectors.groupingBy(classifier, Collectors.averagingDouble(field)));

// Pattern 5: GroupBy + MaxBy
.collect(Collectors.groupingBy(classifier, Collectors.maxBy(comparator)));

// Pattern 6: Sorted + Limit (Top N)
.sorted(comparator.reversed()).limit(n).collect(Collectors.toList());

// Pattern 7: Sorted + Skip + FindFirst (Nth highest)
.map(field).distinct().sorted(reverseOrder()).skip(n-1).findFirst();

// Pattern 8: PartitionBy
.collect(Collectors.partitioningBy(predicate));

// Pattern 9: ToMap
.collect(Collectors.toMap(keyMapper, valueMapper, mergeFunction));

// Pattern 10: Joining
.map(field).collect(Collectors.joining(", "));

// Pattern 11: FlatMap + Distinct
.flatMap(e -> e.getCollection().stream()).distinct().collect(toList());

// Pattern 12: Character frequency (String questions)
str.chars().mapToObj(c -> (char) c).collect(groupingBy(identity(), counting()));

// Pattern 13: Reduce
.reduce(identity, binaryOperator);

// Pattern 14: SummarizingDouble
.collect(Collectors.summarizingDouble(field));

// Pattern 15: Multi-level GroupBy
.collect(groupingBy(field1, groupingBy(field2)));
```

## Q1. Group all employees by their department

## Q3. Find the highest-paid employee

**🔴 MUST PREPARE**
**Companies:** Wells Fargo, JPMorgan, Morgan Stanley, Capgemini, Infosys, TCS, Deloitte
**Difficulty:** Easy
**Interviewer Expectation:** Tests `max()` + `Comparator` + Optional handling.

### Optimized Solution

- Calling `.get()` on Optional without `isPresent()` check — interviewers specifically watch for this
- Using `Comparator.comparing()` instead of `comparingDouble()` for primitive (causes autoboxing)

### Follow-Up
1. "What if the list is empty?" → `max()` returns `Optional.empty()`. Use `orElse(null)` or `orElseThrow()`
2. "What if multiple employees have the same highest salary?" → `max()` returns just one (implementation-dependent which one)
3. "How to find ALL employees with the highest salary?" → Find max first, then filter

## Q4. Find the second-highest salary

**🔴 MUST PREPARE — THE MOST CLASSIC STREAM INTERVIEW QUESTION**
**Companies:** ALL companies — TCS, Infosys, Wipro, Capgemini, Deloitte, Accenture, Cognizant, HCL, Wells Fargo, JPMorgan, Morgan Stanley, startups
**Difficulty:** Medium (Easy to get wrong)
**Interviewer Expectation:** Tests distinct + sorted + skip + findFirst pattern. **THE classic question.**

### Optimized Solution
```java
Optional<Double> secondHighest = employees.stream()
    .map(Employee::getSalary)
    .distinct()                              // ← CRITICAL!
    .sorted(Comparator.reverseOrder())
    .skip(1)
    .findFirst();
// 115000.0 (Arun Prasad)
```

### Common Mistakes (THE INTERVIEW TRAP)
- **Forgetting `distinct()`:** If two employees share the highest salary, skipping 1 still gives the same salary. **This is the #1 elimination mistake.**
- Sorting ascending and using skip(n-1) — works but inefficient for large lists
- Not handling the case where there are fewer than 2 distinct salaries

### Follow-Up Questions (Asked at JPMorgan, Morgan Stanley)
1. "What if all salaries are the same?" → Returns `Optional.empty()` after distinct + skip
2. "Find the Nth highest salary?" → Just change `.skip(N-1)`
3. "Find the second-highest paid EMPLOYEE (not salary)?" → Don't use map; instead sort then skip
   ```java
   Optional<Employee> emp = employees.stream()
       .sorted(Comparator.comparingDouble(Employee::getSalary).reversed())
       .skip(1)
       .findFirst();
   ```
   But this has a bug — if two employees share max salary, skip(1) returns the other top earner, not the second-highest. Better:
   ```java
   double secondHighestSal = employees.stream()
       .map(Employee::getSalary).distinct()
       .sorted(Comparator.reverseOrder()).skip(1).findFirst().orElse(0.0);
   List<Employee> result = employees.stream()
       .filter(e -> e.getSalary() == secondHighestSal)
       .collect(Collectors.toList());
   ```

## Q6. Find employees whose salary is greater than the average company salary

**🔴 MUST PREPARE**
**Companies:** Wells Fargo, JPMorgan, Deloitte, Cognizant, startups
**Difficulty:** Medium
**Interviewer Expectation:** Recognize that this requires TWO stream passes — you cannot compute average and filter in one stream.

### Optimized Solution
```java
double avgSalary = employees.stream()
    .mapToDouble(Employee::getSalary)
    .average()
    .orElse(0.0);

List<Employee> aboveAvg = employees.stream()
    .filter(e -> e.getSalary() > avgSalary)
    .collect(Collectors.toList());
```

### Why Not One Stream?
A stream is consumed once. You need the average BEFORE you can filter. Trying to compute average inline inside filter is impossible because streams don't allow re-iteration.

### Follow-Up
1. "Can you do it in one stream?" → No, not without external state. Streams are designed for single-pass operations.
2. "Performance concern?" → Yes, you iterate twice. For very large datasets, consider a single iterative pass.

## Q17. Convert a for-loop to a stream

**🟡 HIGHLY IMPORTANT** (Asked verbally; tests fundamental thinking)
**Companies:** Wells Fargo, JPMorgan, Morgan Stanley, Cognizant, Deloitte
**Difficulty:** Medium
**Interviewer Expectation:** Recognize iterative patterns and convert them.

### Question: Convert this code to Streams
```java
// Legacy code
List<String> result = new ArrayList<>();
for (Employee e : employees) {
    if (e.isActive() && e.getSalary() > 50000) {
        result.add(e.getFullName().toUpperCase());
    }
}
Collections.sort(result);
```

### Stream Version
```java
List<String> result = employees.stream()
    .filter(Employee::isActive)
    .filter(e -> e.getSalary() > 50000)
    .map(e -> e.getFullName().toUpperCase())
    .sorted()
    .collect(Collectors.toList());
```

### Follow-Up

```java
    if (s1.length() != s2.length()) return false;
    return sortChars(s1).equals(sortChars(s2));

private static String sortChars(String s) {
    return s.chars().sorted()
        .collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append)
        .toString();
```

## Q36. What is wrong with this code? (Debugging Question)

**🟢 GOOD TO KNOW** (Asked at senior interviews)
**Companies:** JPMorgan, Morgan Stanley, Wells Fargo, product companies
**Difficulty:** Medium-Hard
**Interviewer Expectation:** Spot stream reuse bug.

### Buggy Code
```java
Stream<Employee> stream = employees.stream().filter(Employee::isActive);
long count = stream.count();
List<Employee> list = stream.collect(Collectors.toList());  // ← BUG!
```

### What's Wrong?
**Streams are single-use.** After `count()` (terminal operation), the stream is consumed. Calling `collect()` throws `IllegalStateException: stream has already been operated upon or closed`.

### Fix
Create a new stream for each terminal operation:
```java
long count = employees.stream().filter(Employee::isActive).count();
List<Employee> list = employees.stream().filter(Employee::isActive).collect(Collectors.toList());
```

## Q37. What is wrong with this code? (Optional misuse)

**🟢 GOOD TO KNOW**
**Companies:** Wells Fargo, JPMorgan, Deloitte
**Difficulty:** Medium
**Interviewer Expectation:** Spot the .get() anti-pattern.

### Buggy Code
```java
Employee result = employees.stream()
    .filter(e -> "Antarctica".equals(e.getCity()))
    .findFirst()
    .get();    // ← BUG! NoSuchElementException if no match
```

### What's Wrong?
Calling `.get()` on a potentially empty Optional throws `NoSuchElementException`. Always use `orElse()`, `orElseThrow(supplier)`, or `ifPresent()`.

### Fix
```java
Employee result = employees.stream()
    .filter(e -> "Antarctica".equals(e.getCity()))
    .findFirst()
    .orElse(null);          // or orElseThrow(() -> new RuntimeException("Not found"))
```

## Q38. What is wrong with this code? (Lazy evaluation)

**🟢 GOOD TO KNOW**
**Companies:** JPMorgan, Morgan Stanley, product companies
**Difficulty:** Medium
**Interviewer Expectation:** Understand that streams are lazy — no terminal op = nothing executes.

### Buggy Code
```java
employees.stream()
    .filter(e -> {
        System.out.println("Filtering: " + e.getFirstName());
        return e.isActive();
    })
    .map(Employee::getFullName);
// Nothing prints!
```

### What's Wrong?
There's no terminal operation. Streams are lazy — without `collect`, `forEach`, `count`, etc., NOTHING executes. The println never runs.

### Fix
Add a terminal operation:
```java
List<String> names = employees.stream()
    .filter(e -> {
        System.out.println("Filtering: " + e.getFirstName());
        return e.isActive();
    })
    .map(Employee::getFullName)
    .collect(Collectors.toList());     // ← Terminal operation triggers execution
```

# ⚠ MOST DANGEROUS TRICKY QUESTIONS

These are questions where candidates GET ELIMINATED. Master them.

### #1: Second-highest salary WITHOUT `distinct()`
The bug is invisible until you have duplicate top salaries. Always remember distinct.

### #2: `toMap()` with duplicate keys
Without a merge function, you get `IllegalStateException`. Always assume duplicates possible.

### #3: NPE on `equals()` with null fields
`e.getDepartment().equals("X")` crashes on null. Always write `"X".equals(e.getDepartment())`.

### #4: Calling `.get()` on Optional
Interviewers actively look for this. Always use `orElse()`, `orElseThrow()`, or `ifPresent()`.

### #5: Reusing a consumed stream
After a terminal operation, the stream is dead. Create a new stream.

### #6: `allMatch()` on empty stream returns `true` (vacuous truth)
This trips up many candidates. Remember: empty stream + allMatch = true.

### #7: `peek()` without terminal operation
peek is lazy. Nothing executes without a terminal. Used wrongly, it produces zero output.

### #8: Forgetting that streams don't modify the source
A common confusion. `employees.stream().filter(...)` doesn't change `employees`.
