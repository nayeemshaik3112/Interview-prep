Before jumping to questions, here is the realistic difficulty mapping you should keep in mind. Company expectations differ a lot, and matching your prep to the tier saves you from wasting time.

**Tier 1 — Easy/Light Medium (Infosys, TCS, Capgemini, Cognizant):**
1 problem, mostly Array/String basics — reverse string, palindrome, anagram, second largest, rotate array, missing number. Brute force often acceptable if you explain it well.

**Tier 2 — Solid Medium (Wipro, Accenture, IBM, Deloitte):**
1-2 problems. They genuinely care about brute → optimized walkthrough. Common: Two Sum, Kadane, Move Zeros, Longest Substring Without Repeats, Valid Parentheses, Subarray with Sum, First Non-Repeating Character.

**Tier 3 — Medium-Hard (Wells Fargo, mid-stage startups):**
2 coding rounds. Sliding window + HashMap heavy. Expect: Subarray Sum K, Group Anagrams, Three Sum, Trapping Rain Water (sometimes), Min Window Substring, Top K Frequent.

**Tier 4 — Product Companies (Amazon, Adobe, Walmart, Flipkart):**
Two-pointer + monotonic stack + sliding window mastery expected. Sliding Window Max, Daily Temperatures, Container With Most Water, Longest Consecutive Sequence.

**Top 10 most-repeated questions across all tiers:**
Two Sum, Reverse String/Words, Anagram check, Longest Substring Without Repeating, Kadane, First Non-Repeating Char, Valid Parentheses, Move Zeros, Subarray Sum K, Best Time to Buy/Sell Stock.

### Q1. Second Largest Element in Array

**Difficulty:** Easy

**Asked In:**
- Infosys
- TCS
- Wipro
- Capgemini
- Cognizant
- Accenture (warm-up round)

**Interviewer Expectation:**
The interviewer wants to check whether you go for the obvious sort-based answer or actually think about it. They want a single-pass O(n) solution, and they will almost always throw a duplicate-array follow-up to catch you off-guard.

**Optimized Explanation:**
Maintain two variables — `first` (largest so far) and `second` (second largest so far). Walk through the array once. When you find a value greater than `first`, the old `first` slides down to `second`, and the new value takes `first`. Important catch: if the value equals `first`, skip it — otherwise duplicates corrupt your `second`.

**Optimized Java Solution:**
```java
public static int secondLargest(int[] arr) {
    if (arr == null || arr.length < 2) return -1;
    int first = Integer.MIN_VALUE, second = Integer.MIN_VALUE;
    for (int n : arr) {
        if (n > first) { second = first; first = n; }
        else if (n > second && n != first) { second = n; }
    }
    return second == Integer.MIN_VALUE ? -1 : second;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Sorting and returning `arr[n-2]` — fails on `[5,5,4]`
- Forgetting the `n != first` guard
- Not handling array length < 2

**Follow-up Tricky Questions:**
- How would you find the Kth largest? (min-heap of size K)
- Can you solve it on a stream of numbers without storing the array?
- What changes for the second smallest?

### Q2. Find the Duplicate Number

**Difficulty:** Medium

**Asked In:**
- Accenture
- Wipro
- Wells Fargo
- Startups
- Product companies (follow-up version)

**Interviewer Expectation:**
Numbers are in range `[1..n]` in an array of size `n+1`. Interviewer wants to see if you can think beyond nested loops. HashSet is acceptable, but for a senior candidate they often expect the O(1)-space cycle-detection trick.

**Optimized Explanation:**
The straightforward HashSet approach catches duplicates in one pass. For a stronger answer, mention Floyd's cycle detection — treat the array as a linked list where `arr[i]` is the next pointer. A duplicate means two indices point to the same value, which creates a cycle.

**Optimized Java Solution:**
```java
public static int findDuplicate(int[] arr) {
    Set<Integer> seen = new HashSet<>();
    for (int n : arr) {
        if (!seen.add(n)) return n;
    }
    return -1;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n) — mention Floyd's trick to bring it down to O(1)

**Common Mistakes:**
- Forgetting `HashSet.add()` returns `false` on duplicate
- Modifying input (sign-marking trick) without asking permission
- Assuming only one duplicate exists when interviewer hasn't said so

**Follow-up Tricky Questions:**
- Can you do it in O(1) extra space without modifying the array? (Floyd's)
- What if there are multiple duplicates? Find all of them.
- What if numbers are not constrained to `[1..n]`?

### Q3. Remove Duplicates from Sorted Array (In-Place)

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Infosys
- Wipro
- Capgemini
- Accenture

**Interviewer Expectation:**
The catch here is "in-place." Java arrays are fixed-size, so you cannot truly delete — you overwrite. The interviewer is checking whether you know the two-pointer write-index pattern.

**Optimized Explanation:**
Use a slow pointer `i` (points to last unique position) and a fast pointer `j` (scans ahead). Whenever `arr[j] != arr[i]`, you have a new unique value — increment `i` and copy `arr[j]` there. Return `i+1` as the new length.

**Optimized Java Solution:**
```java
public static int removeDuplicatesSorted(int[] arr) {
    if (arr.length == 0) return 0;
    int i = 0;
    for (int j = 1; j < arr.length; j++) {
        if (arr[j] != arr[i]) {
            i++;
            arr[i] = arr[j];
        }
    }
    return i + 1;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Creating a new array (defeats the "in-place" requirement)
- Trying to "delete" elements (impossible with primitive arrays)
- Off-by-one when returning the new length

**Follow-up Tricky Questions:**
- What if each element can appear at most twice?
- What if the array is unsorted? (LinkedHashSet, or sort first)
- Can you do this for a sorted ArrayList?

### Q4. Rotate Array by K Positions

**Difficulty:** Medium

**Asked In:**
- Wipro
- Accenture
- Cognizant
- Wells Fargo
- Startups

**Interviewer Expectation:**
Most candidates write the obvious "rotate one step, k times" loop — that's O(n*k) and gets you eliminated. The interviewer wants the reversal trick, which is a clean O(n) time, O(1) space solution.

**Optimized Explanation:**
The reversal trick has three steps:
1. Reverse the entire array
2. Reverse the first K elements
3. Reverse the remaining N-K elements

This works because rotating right by K is equivalent to splitting the array at position N-K and swapping halves. Don't forget `k = k % n` when `k > n`.

**Optimized Java Solution:**
```java
public static void rotateRight(int[] arr, int k) {
    int n = arr.length;
    if (n == 0) return;
    k = k % n;
    reverse(arr, 0, n - 1);
    reverse(arr, 0, k - 1);
    reverse(arr, k, n - 1);
}
private static void reverse(int[] a, int l, int r) {
    while (l < r) { int t = a[l]; a[l++] = a[r]; a[r--] = t; }
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Using an extra array (works but wastes space)
- Forgetting `k = k % n`
- Confusing left rotation with right rotation

**Follow-up Tricky Questions:**
- How would you do left rotation with the same trick?
- What if K is negative?
- Can you rotate a linked list by K? (similar idea, find length first)

### Q5. Move Zeros to End

**Difficulty:** Easy-Medium

**Asked In:**
- Accenture
- Wipro
- Infosys
- Startups
- Adobe

**Interviewer Expectation:**
Constraints: preserve the order of non-zero elements, do it in-place. This is a foundation two-pointer pattern, and they want to see you write it cleanly without bugs.

**Optimized Explanation:**
Use a write-index pointer that starts at 0. Scan the array — every time you see a non-zero, copy it to the write position and increment. After the first pass, fill the rest of the array with zeros. Single pass with two phases — clean and bug-free.

**Optimized Java Solution:**
```java
public static void moveZeros(int[] arr) {
    int write = 0;
    for (int n : arr) if (n != 0) arr[write++] = n;
    while (write < arr.length) arr[write++] = 0;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Using an auxiliary array (loses points on "in-place" check)
- Swapping zeros incorrectly when multiple zeros are adjacent
- Not preserving relative order of non-zero elements

**Follow-up Tricky Questions:**
- Move all negatives to one side, positives to the other?
- Sort 0s, 1s, and 2s in-place? (Dutch National Flag)
- Can you do this in a single pass using swap?

### Q6. Merge Two Sorted Arrays

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Infosys
- Wipro
- Wells Fargo
- Accenture

**Interviewer Expectation:**
Foundational merge-step of merge sort. They want clean two-pointer code, no off-by-one, and good handling of the leftover elements after one array is exhausted.

**Optimized Explanation:**
Two pointers, one on each array. At each step, copy the smaller element into the result and advance that pointer. After the main loop, one of the arrays will still have leftover elements — drain them with two tail loops.

**Optimized Java Solution:**
```java
public static int[] mergeSorted(int[] a, int[] b) {
    int i = 0, j = 0, k = 0;
    int[] res = new int[a.length + b.length];
    while (i < a.length && j < b.length) {
        res[k++] = (a[i] <= b[j]) ? a[i++] : b[j++];
    }
    while (i < a.length) res[k++] = a[i++];
    while (j < b.length) res[k++] = b[j++];
    return res;
}
```

**Time Complexity:** O(m + n)

**Space Complexity:** O(m + n)

**Common Mistakes:**
- Forgetting to drain the leftover elements
- Using `<` instead of `<=` (breaks stability)
- Incorrect index handling when the arrays have different sizes

**Follow-up Tricky Questions:**
- Can you merge in-place when `nums1` has trailing zeros as buffer? (fill from the back)
- Merge K sorted arrays? (min-heap)
- What if the arrays are streams and you can't load them fully?

### Q7. Find Min and Max in a Single Pass

**Difficulty:** Easy

**Asked In:**
- Infosys
- TCS
- Capgemini
- Cognizant

**Interviewer Expectation:**
A warm-up question. They are checking if you initialize variables correctly — many candidates initialize `min = 0` or `max = 0`, which silently breaks on all-negative or all-positive arrays.

**Optimized Explanation:**
Initialize both `min` and `max` from `arr[0]`. Then iterate from index 1 — update either `min` or `max`. Using `else if` is a small optimization (one comparison per element instead of two).

**Optimized Java Solution:**
```java
public static int[] minMax(int[] arr) {
    int min = arr[0], max = arr[0];
    for (int n : arr) {
        if (n < min) min = n;
        else if (n > max) max = n;
    }
    return new int[]{min, max};
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Initializing `min = 0, max = 0`
- Using `Integer.MAX_VALUE` and `MIN_VALUE` but then not handling empty array
- Two separate loops instead of one

**Follow-up Tricky Questions:**
- Can you do it in fewer than 2n comparisons? (Tournament method, ~1.5n)
- Find both in a stream of integers
- What if the array is rotated sorted?

### Q8. Kadane's Algorithm — Maximum Subarray Sum

**Difficulty:** Medium

**Asked In:**
- Accenture
- Wells Fargo
- Deloitte
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
This is a classic — they want to see if you recognize the pattern instantly. The dangerous follow-up: "what if all numbers are negative?" trips up candidates who initialize `maxSoFar = 0`.

**Optimized Explanation:**
At every index, you have a choice: extend the previous subarray (`curr + arr[i]`) or restart from current element (`arr[i]`). Take whichever is larger. Keep updating the overall maximum.

The intuition: if `curr` becomes negative, it can only hurt future sums, so it's better to drop and restart.

**Optimized Java Solution:**
```java
public static int maxSubArraySum(int[] arr) {
    int maxSoFar = arr[0], curr = arr[0];
    for (int i = 1; i < arr.length; i++) {
        curr = Math.max(arr[i], curr + arr[i]);
        maxSoFar = Math.max(maxSoFar, curr);
    }
    return maxSoFar;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Initializing `maxSoFar = 0` (fails on all-negative arrays)
- Resetting `curr` to 0 instead of `arr[i]`
- Not handling single-element arrays

**Follow-up Tricky Questions:**
- Return the actual subarray (not just the sum) — track start/end indices
- Maximum product subarray? (track both min and max — negatives flip sign)
- What if the array is circular?
- Maximum subarray with length ≥ K?

### Q9. Subarray with Given Sum (Positive Numbers)

**Difficulty:** Medium

**Asked In:**
- Wipro
- Accenture
- Wells Fargo
- Startups

**Interviewer Expectation:**
The interviewer expects you to recognize this as a sliding window problem (because positive numbers mean the sum grows monotonically as you expand). The very next follow-up is "what if negatives are allowed?" — and that's when sliding window breaks.

**Optimized Explanation:**
Expand the window by adding `arr[right]`. If the sum overshoots, shrink from the left until it fits. If you hit the target exactly, return the indices. Works only because all numbers are positive — adding always grows, subtracting always shrinks.

**Optimized Java Solution:**
```java
public static int[] subarrayWithSum(int[] arr, int target) {
    int left = 0, sum = 0;
    for (int right = 0; right < arr.length; right++) {
        sum += arr[right];
        while (sum > target && left <= right) sum -= arr[left++];
        if (sum == target) return new int[]{left, right};
    }
    return new int[]{-1, -1};
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Using sliding window when negatives are allowed (breaks the monotonicity)
- Forgetting `left <= right` guard in the shrink loop
- Returning length instead of indices

**Follow-up Tricky Questions:**
- What if negatives are allowed? (Switch to prefix sum + HashMap)
- Find the count of all such subarrays, not just one
- Smallest subarray with sum ≥ target?

### Q10. Longest Subarray with Sum K (Handles Negatives)

**Difficulty:** Medium-Hard

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Product companies

**Interviewer Expectation:**
This is the follow-up trap after Q9. The moment negatives enter, sliding window dies. They want you to switch to the prefix-sum + HashMap pattern — a very common interview pattern.

**Optimized Explanation:**
Maintain a running prefix sum. For each index, if `prefix - k` already exists in the map, then the subarray between that earlier index and the current one sums to k. Always store the *earliest* occurrence of each prefix sum, so the length is maximized.

Seed the map with `(0, -1)` to handle subarrays that start from index 0.

**Optimized Java Solution:**
```java
public static int longestSubarraySumK(int[] arr, int k) {
    Map<Integer, Integer> map = new HashMap<>();
    map.put(0, -1);
    int prefix = 0, best = 0;
    for (int i = 0; i < arr.length; i++) {
        prefix += arr[i];
        if (map.containsKey(prefix - k))
            best = Math.max(best, i - map.get(prefix - k));
        map.putIfAbsent(prefix, i);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Using `put` instead of `putIfAbsent` (overwrites earliest occurrence)
- Forgetting the `(0, -1)` seed entry
- Using sliding window because the array "looks similar" to Q9

**Follow-up Tricky Questions:**
- Count all subarrays with sum K (use frequency instead of earliest index)
- Longest subarray with equal 0s and 1s? (replace 0 with -1, find sum = 0)
- Longest subarray divisible by K?

### Q11. Majority Element (Appears > n/2 Times)

**Difficulty:** Medium

**Asked In:**
- Wipro
- Cognizant
- Startups
- Accenture

**Interviewer Expectation:**
HashMap solution is acceptable, but the interviewer is hoping you know Boyer-Moore — O(n) time with O(1) space. The trick is elegant and often surprises candidates who only know counting approaches.

**Optimized Explanation:**
Boyer-Moore Voting: pair up votes — every non-majority element cancels one majority vote, but since majority appears more than n/2 times, it always survives. Maintain a `count` and a `candidate`. When `count == 0`, switch to the current element. Increment if match, decrement otherwise.

**Optimized Java Solution:**
```java
public static int majorityElement(int[] arr) {
    int count = 0, candidate = 0;
    for (int n : arr) {
        if (count == 0) candidate = n;
        count += (n == candidate) ? 1 : -1;
    }
    return candidate;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Assuming a majority element always exists (verify with a second pass if not guaranteed)
- Confusing "majority" (> n/2) with "mode" (most frequent)
- Using HashMap when O(1) space is requested

**Follow-up Tricky Questions:**
- Find elements that appear more than n/3 times? (at most 2, modified Boyer-Moore)
- Find elements appearing more than n/K times?
- What if the array is a stream?

### Q12. Missing Number (Range [0..n], One Missing)

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Infosys
- Wipro
- Capgemini
- Accenture

**Interviewer Expectation:**
Multiple valid solutions — sum formula, XOR, HashSet. The interviewer wants you to discuss trade-offs. XOR is the most defensible because it doesn't overflow.

**Optimized Explanation:**
Two clean approaches:
1. **Sum formula:** expected sum is `n*(n+1)/2`, actual sum from array. Difference is the missing number. Risk: integer overflow for large n.
2. **XOR:** XOR all indices and all values. Identical values cancel out, leaving only the missing number. No overflow risk.

**Optimized Java Solution:**
```java
public static int missingNumber(int[] arr) {
    int n = arr.length, xor = n;
    for (int i = 0; i < n; i++) xor ^= i ^ arr[i];
    return xor;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Integer overflow with sum approach (use `long` if you use sum)
- Off-by-one on the range
- Missing the `xor = n` initialization

**Follow-up Tricky Questions:**
- Two numbers missing? (sum and sum of squares, or partition by XOR bit)
- Missing positive integer in unsorted array?
- Find duplicate and missing together?

### Q13. Sort Colors — Dutch National Flag

**Difficulty:** Medium

**Asked In:**
- Accenture
- Wells Fargo
- Adobe
- Startups
- Amazon

**Interviewer Expectation:**
Two passes (count 0s, 1s, 2s and refill) is acceptable, but they want the single-pass three-pointer solution. Tests whether you can think with multiple pointers without losing track.

**Optimized Explanation:**
Three pointers — `low` (next 0 position), `mid` (current element), `high` (next 2 position). Sweep with `mid`:
- If `arr[mid] == 0` → swap with `low`, advance both
- If `arr[mid] == 1` → just advance `mid`
- If `arr[mid] == 2` → swap with `high`, decrement `high` (don't advance `mid` yet — the swapped-in value isn't checked)

**Optimized Java Solution:**
```java
public static void sortColors(int[] arr) {
    int low = 0, mid = 0, high = arr.length - 1;
    while (mid <= high) {
        switch (arr[mid]) {
            case 0: swap(arr, low++, mid++); break;
            case 1: mid++; break;
            case 2: swap(arr, mid, high--); break;
        }
    }
}
private static void swap(int[] a, int i, int j) {
    int t = a[i]; a[i] = a[j]; a[j] = t;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Advancing `mid` after swapping with `high` (you haven't checked the new value yet)
- Using `Arrays.sort()` (defeats the purpose of the question)
- Confusing loop termination — it's `mid <= high`, not `mid < high`

**Follow-up Tricky Questions:**
- What if there are K colors? (counting sort)
- Sort by parity (evens then odds)?
- Why is two-pass simpler but worse?

### Q14. Best Time to Buy and Sell Stock (Single Transaction)

**Difficulty:** Easy-Medium

**Asked In:**
- Accenture
- Wipro
- Wells Fargo
- Startups
- Amazon

**Interviewer Expectation:**
A classic. The brute force O(n²) is obvious — they want O(n). The trick is realizing that for each day, you only need the minimum price seen so far.

**Optimized Explanation:**
As you walk through prices, keep track of the lowest price seen so far. At each day, compute potential profit as `today - minSoFar` and update the best. Single pass, two variables.

**Optimized Java Solution:**
```java
public static int maxProfit(int[] prices) {
    int minSoFar = Integer.MAX_VALUE, best = 0;
    for (int p : prices) {
        if (p < minSoFar) minSoFar = p;
        else best = Math.max(best, p - minSoFar);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Trying to find `max - min` directly (ignores the order constraint — buy before sell)
- Initializing `best = -1` (problem expects 0 if no profit possible)
- Confusing it with the multi-transaction variant

**Follow-up Tricky Questions:**
- Unlimited transactions? (sum every positive `prices[i] - prices[i-1]`)
- At most 2 transactions? (more advanced — usually not asked at 3-yr level)
- Include transaction fee?
- With a cooldown period?

### Q15. Product of Array Except Self (No Division)

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Amazon
- Adobe
- Startups
- Product companies

**Interviewer Expectation:**
"No division" is the key constraint. Naive O(n²) is to multiply all but skip current. They want O(n) using prefix and suffix products. Bonus points for doing it with O(1) extra space.

**Optimized Explanation:**
Two passes:
1. First pass: store the product of everything to the LEFT of index `i` in `res[i]`
2. Second pass: keep a running `right` product and multiply it into `res[i]`

`res[i] = leftProduct[i] * rightProduct[i]`. The output array doesn't count as extra space, so this is O(1) extra.

**Optimized Java Solution:**
```java
public static int[] productExceptSelf(int[] arr) {
    int n = arr.length;
    int[] res = new int[n];
    res[0] = 1;
    for (int i = 1; i < n; i++) res[i] = res[i-1] * arr[i-1];
    int right = 1;
    for (int i = n - 1; i >= 0; i--) {
        res[i] *= right;
        right *= arr[i];
    }
    return res;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1) extra (output not counted)

**Common Mistakes:**
- Using division (`total / arr[i]`) — fails when zeros exist
- Building separate `left[]` and `right[]` arrays — wastes space
- Off-by-one in the prefix/suffix index logic

**Follow-up Tricky Questions:**
- What if division is allowed? (handle zero count: 0, 1, or 2+)
- Modify so the result fits in 32-bit integer (mod the product)
- Same logic but for division (sum except self)?

### Q16. Two Sum (Unsorted Array)

**Difficulty:** Easy-Medium

**Asked In:**
- Infosys
- TCS
- Wipro
- Accenture
- Wells Fargo
- Every product company (foundation question)

**Interviewer Expectation:**
The most-asked DSA question in the world. Brute O(n²) is the "warm up your thinking" answer. They want the O(n) HashMap solution and may follow up with "what if the array is sorted?" — that's the two-pointer variant.

**Optimized Explanation:**
Walk the array. For each element, compute its complement (`target - current`). If the complement is already in the map, you've found the pair. Otherwise, store the current element with its index for future lookups.

**Optimized Java Solution:**
```java
public static int[] twoSum(int[] arr, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < arr.length; i++) {
        int need = target - arr[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(arr[i], i);
    }
    return new int[]{-1, -1};
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Storing current element BEFORE the check (creates a false positive when `arr[i] * 2 == target`)
- Returning the values instead of indices (or vice versa)
- Forgetting that interviewer may want all pairs, not just first

**Follow-up Tricky Questions:**
- What if the array is sorted? (two-pointer, O(1) space)
- Find ALL pairs that sum to target
- Find pairs that sum closest to target
- Extend to Three Sum / Four Sum

### Q17. Reverse a String

**Difficulty:** Easy

**Asked In:**
- Infosys
- TCS
- Wipro
- Capgemini
- Cognizant

**Interviewer Expectation:**
A warm-up. The interviewer just wants to see clean code and knowledge that Java strings are immutable. Either `char[]` swap or `StringBuilder.reverse()` is fine — but using `String += s.charAt(i)` in a loop is a red flag.

**Optimized Explanation:**
Convert to `char[]` so you can mutate. Use two pointers from both ends, swap, move inward. Done. If interviewer allows, `new StringBuilder(s).reverse().toString()` is the one-liner version.

**Optimized Java Solution:**
```java
public static String reverseString(String s) {
    char[] c = s.toCharArray();
    int l = 0, r = c.length - 1;
    while (l < r) { char t = c[l]; c[l++] = c[r]; c[r--] = t; }
    return new String(c);
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n) (because of char array; Java strings are immutable)

**Common Mistakes:**
- Using `String` concatenation in a loop (creates O(n²) garbage)
- Using `==` instead of `.equals()` to verify
- Forgetting that String is immutable

**Follow-up Tricky Questions:**

### Q18. Check Palindrome (Ignore Case, Alphanumeric Only)

**Difficulty:** Easy-Medium

**Asked In:**
- Infosys
- TCS
- Wipro
- Capgemini
- Accenture

**Interviewer Expectation:**

**Optimized Explanation:**
Two pointers from both ends. Skip non-alphanumeric characters. Compare letters case-insensitively. If you ever find a mismatch, return false. If pointers cross, it's a palindrome.

**Optimized Java Solution:**
```java
public static boolean isPalindrome(String s) {
    int l = 0, r = s.length() - 1;
    while (l < r) {
        while (l < r && !Character.isLetterOrDigit(s.charAt(l))) l++;
        while (l < r && !Character.isLetterOrDigit(s.charAt(r))) r--;
        if (Character.toLowerCase(s.charAt(l++)) !=
            Character.toLowerCase(s.charAt(r--))) return false;
    }
    return true;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Not asking the clarifying questions
- Comparing without lowering case
- Using `s.equals(reverse(s))` — works but wastes O(n) space

### Q19. Check Anagram

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Infosys
- Wipro
- Accenture
- Capgemini

**Interviewer Expectation:**
Sort-based solution is the obvious one — they want the frequency-array approach in O(n). They may follow up with "what if the string has Unicode characters?" — your fixed `int[26]` would fail.

**Optimized Explanation:**
If lengths differ → not an anagram. Use a frequency array of size 26 (for lowercase letters). Increment for one string, decrement for the other. At the end, if all counts are zero, they're anagrams.

**Optimized Java Solution:**
```java
public static boolean isAnagram(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] freq = new int[26];
    for (int i = 0; i < a.length(); i++) {
        freq[a.charAt(i) - 'a']++;
        freq[b.charAt(i) - 'a']--;
    }
    for (int f : freq) if (f != 0) return false;
    return true;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1) (fixed alphabet)

**Common Mistakes:**
- Forgetting the length-check shortcut
- Using `int[256]` when the problem says lowercase letters (still works but signals laziness)
- Sorting both strings (O(n log n) — acceptable but slower)

**Follow-up Tricky Questions:**
- What if Unicode characters? (use `HashMap<Character, Integer>`)
- Group anagrams from a list of strings
- Find all anagram substrings of a pattern in a text

### Q21. Longest Substring Without Repeating Characters

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Accenture
- Startups
- Adobe
- Amazon
- Flipkart

**Interviewer Expectation:**
The flagship sliding window question. They expect you to know the template and handle the "left pointer should only move forward" trap. Brute force O(n²) is acceptable as warm-up but they want O(n).

**Optimized Explanation:**
Sliding window with a HashMap of `character → last seen index`. Expand `right` one at a time. If you see a repeated character, jump `left` to one past its last occurrence — but only if that's actually forward (`Math.max(left, lastSeen + 1)`). The window length is `right - left + 1`.

**Optimized Java Solution:**
```java
public static int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> map = new HashMap<>();
    int best = 0, left = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        if (map.containsKey(c)) left = Math.max(left, map.get(c) + 1);
        map.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(min(n, alphabet size))

**Common Mistakes:**
- Setting `left = map.get(c) + 1` directly (causes regression when duplicate is outside the window)
- Forgetting to update the map AFTER the left adjustment
- Off-by-one on window length

**Follow-up Tricky Questions:**
- Return the substring itself (not just length)
- Longest substring with at most K distinct characters
- Longest substring with exactly K distinct characters
- What if the alphabet is unbounded (Unicode)?

### Q25. String Compression (Run-Length Encoding)

**Difficulty:** Medium

**Asked In:**
- Accenture
- Wells Fargo
- Startups
- Adobe
- Amazon

**Interviewer Expectation:**
Standard StringBuilder problem. The variant they may ask: return the original string if compression doesn't actually shorten it (e.g., `"abc"` → `"a1b1c1"` is *longer*).

**Optimized Explanation:**
Two pointers — `i` marks the start of a run, `j` scans to the end of the run. Append the character and the run length to the result. Move `i` to `j` and continue.

**Optimized Java Solution:**
```java
public static String compress(String s) {
    StringBuilder sb = new StringBuilder();
    int n = s.length(), i = 0;
    while (i < n) {
        int j = i;
        while (j < n && s.charAt(j) == s.charAt(i)) j++;
        sb.append(s.charAt(i)).append(j - i);
        i = j;
    }
    return sb.toString();
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Using nested loops awkwardly without two pointers
- Forgetting that count > 9 needs multiple digits in the output
- Concatenating instead of using StringBuilder

**Follow-up Tricky Questions:**
- Return the shorter of original vs compressed
- Decompress back to the original string
- Compress in-place using a `char[]` (LeetCode 443 variant)

### Q27. Longest Common Prefix

**Difficulty:** Easy-Medium

**Asked In:**
- Accenture
- Wipro
- Startups

- TCS

**Interviewer Expectation:**

**Optimized Explanation:**
Pick the first string as the reference. For each character position, check whether all other strings have the same character. The moment you find a mismatch or run off the end of any string, return what you've matched so far.

**Optimized Java Solution:**
```java
public static String longestCommonPrefix(String[] strs) {
    if (strs == null || strs.length == 0) return "";
    for (int i = 0; i < strs[0].length(); i++) {
        char c = strs[0].charAt(i);
        for (int j = 1; j < strs.length; j++) {
            if (i == strs[j].length() || strs[j].charAt(i) != c)
                return strs[0].substring(0, i);
        }
    }
    return strs[0];
}
```

**Time Complexity:** O(N * M) where N = strings, M = shortest length

**Space Complexity:** O(1) extra

**Common Mistakes:**
- Forgetting to handle the empty array
- Going beyond the length of a shorter string (index out of bounds)
- Sorting unnecessarily — works, but slower than vertical scan

**Follow-up Tricky Questions:**
- Find the longest common suffix
- Find the longest common substring (different problem, harder)
- What if strings are streams?

### Q28. Valid Parentheses

**Difficulty:** Easy-Medium

**Asked In:**
- Every company (Infosys, TCS, Wipro, Accenture, Wells Fargo, startups, Amazon)
- Foundation stack question

**Interviewer Expectation:**
Pure stack pattern. They want to see you use `Deque<Character>` (or `ArrayDeque`), not the legacy `Stack` class. They will absolutely check the "empty stack at the end" edge case.

**Optimized Explanation:**
Iterate the string. For each opening bracket, push onto stack. For each closing bracket, pop and check it matches. After the loop, the stack must be empty — otherwise there are unmatched opens.

**Optimized Java Solution:**
```java
public static boolean isValidBrackets(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') st.push(c);
        else {
            if (st.isEmpty()) return false;
            char top = st.pop();
            if ((c == ')' && top != '(') ||
                (c == ']' && top != '[') ||
                (c == '}' && top != '{')) return false;
        }
    }
    return st.isEmpty();
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Forgetting the final `st.isEmpty()` check (returns true for `"(("`)
- Popping from an empty stack (NullPointerException / EmptyStackException)
- Using the legacy `Stack` class instead of `Deque`

**Follow-up Tricky Questions:**
- Find the longest valid parenthesis substring
- Remove the minimum number of invalid parens to make it valid
- Same problem but with only `(` and `)` — can you do O(1) space?

public static List<List<String>> groupAnagrams(String[] strs) {

### Q31. Contains Duplicate Within Distance K

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Deloitte

**Interviewer Expectation:**
Direct extension of Q30 with a sliding window twist. They want you to combine `HashSet` with index tracking, or use a sliding-window `HashSet`.

**Optimized Explanation:**
Maintain a `HashSet` of the last K elements (a sliding window). For each new element, check if it already exists in the set — that's a duplicate within distance K. After adding, if the window exceeds size K, remove the element at `i - k`.

**Optimized Java Solution:**
```java
public static boolean containsNearbyDuplicate(int[] arr, int k) {
    Set<Integer> window = new HashSet<>();

        if (window.size() > k) window.remove(arr[i - k]);
    }
    return false;
}
```

**Time Complexity:** O(n)

### Q32. Subarray Sum Equals K (Negatives Allowed)

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Accenture
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
The prefix-sum + HashMap pattern. This is the moment they distinguish candidates who only know sliding window from those who know prefix-sum tricks too. Seed the map with `(0, 1)` — that's the catch.

**Optimized Explanation:**
Build a running prefix sum. For each index, if `prefix - k` has been seen before, then a subarray ending here sums to k. Use a frequency map of prefix sums to count how many such subarrays exist (not just one).

The `(0, 1)` seed handles the case where the subarray starts from index 0 — the "empty prefix" has sum 0, occurring once.

**Optimized Java Solution:**
```java
public static int subarraySumEqualsK(int[] arr, int k) {
    Map<Integer, Integer> map = new HashMap<>();
    map.put(0, 1);
    int prefix = 0, count = 0;
    for (int n : arr) {
        prefix += n;
        count += map.getOrDefault(prefix - k, 0);
        map.merge(prefix, 1, Integer::sum);
    }
    return count;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Forgetting the `(0, 1)` seed
- Using sliding window (fails with negatives)
- Incrementing the map BEFORE the lookup (causes a single-element double-count)

**Follow-up Tricky Questions:**
- Return the *count* vs the *longest* such subarray
- Find subarray with sum divisible by K
- Find subarray with equal 0s and 1s (transform 0 → -1)

### Q33. Longest Consecutive Sequence

**Difficulty:** Medium-Hard

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
Sorting gives O(n log n) — acceptable but not what they want. They want the HashSet trick that achieves true O(n). The key insight is starting expansion only from sequence "heads".

**Optimized Explanation:**
Put every number in a HashSet. Iterate through the set. For each number `n`, check if `n-1` is NOT in the set — if so, `n` is the start of a sequence. Walk forward (`n+1`, `n+2`, ...) and count. This guarantees each number is visited at most twice, giving O(n) total.

**Optimized Java Solution:**
```java
public static int longestConsecutive(int[] arr) {
    Set<Integer> set = new HashSet<>();
    for (int n : arr) set.add(n);
    int best = 0;
    for (int n : set) {
        if (!set.contains(n - 1)) {
            int len = 1, cur = n;
            while (set.contains(cur + 1)) { cur++; len++; }
            best = Math.max(best, len);
        }
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Walking the sequence from every number (becomes O(n²))
- Iterating the array instead of the set (counts duplicates extra)
- Using sorting and not mentioning the HashSet trick

**Follow-up Tricky Questions:**
- Return the sequence itself, not just length
- What if duplicates count as separate values?
- Longest consecutive sequence in a binary tree?

### Q35. Find All Duplicates in an Array (Range [1..n])

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Accenture

**Interviewer Expectation:**
The cleanest O(1) extra-space solution is sign-marking. They will ask "can you do it without modifying the input?" — answer: HashSet is needed if mutation is forbidden.

**Optimized Explanation:**
Since all values are in `[1..n]`, you can use the array itself as a hash. For each value `v`, go to index `|v| - 1` and negate that cell. If you arrive at an already-negative cell, the value was seen before — it's a duplicate.

**Optimized Java Solution:**
```java
public static List<Integer> findAllDuplicates(int[] arr) {
    List<Integer> res = new ArrayList<>();
    for (int i = 0; i < arr.length; i++) {
        int idx = Math.abs(arr[i]) - 1;
        if (arr[idx] < 0) res.add(idx + 1);
        else arr[idx] = -arr[idx];
    }
    return res;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1) extra

**Common Mistakes:**
- Forgetting `Math.abs` when computing the index (values are being negated)
- Modifying input without asking the interviewer
- Off-by-one between value and index (value `v` → index `v - 1`)

**Follow-up Tricky Questions:**
- Find all missing numbers in `[1..n]`
- Find both duplicates and missing in one pass
- What if you can't modify the input?

Min-heap of size K is the classic answer. Mentioning bucket sort for O(n) earns bonus points. Don't sort the entire frequency map by value — that's O(n log n), worse than the heap.

**Optimized Explanation:**
Build a frequency map. Push entries into a min-heap of size K, keyed by frequency. Whenever heap exceeds size K, pop the smallest. At the end, the heap contains the top K. Extract them.

**Optimized Java Solution:**
```java
public static int[] topKFrequent(int[] arr, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int n : arr) freq.merge(n, 1, Integer::sum);
    PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[1] - y[1]);
    for (var e : freq.entrySet()) {
        pq.offer(new int[]{e.getKey(), e.getValue()});
        if (pq.size() > k) pq.poll();
    }
    int[] res = new int[k];
    for (int i = k - 1; i >= 0; i--) res[i] = pq.poll()[0];
    return res;
}
```

**Time Complexity:** O(n log k)

**Space Complexity:** O(n)

**Common Mistakes:**
- Using max-heap of size N (works but uses more memory)
- Comparator direction wrong — min-heap needs `x[1] - y[1]`
- Sorting the entire map (slower than heap approach)

**Follow-up Tricky Questions:**
- Achieve O(n) with bucket sort
- Top K frequent strings? (same idea, comparator on string)
- Top K largest elements (not frequency-based)?

### Q37. Isomorphic Strings

**Difficulty:** Easy-Medium

**Asked In:**
- Accenture
- Wipro
- Startups
- Wells Fargo

**Interviewer Expectation:**
The catch is that mapping must be BIDIRECTIONAL — `"egg"` to `"add"` works, but `"foo"` to `"bar"` doesn't (both `o`s would map to `a` and `r` — collision). Two maps, or a clever single-int-array trick.

**Optimized Explanation:**
Maintain two arrays of size 256 (`mapS` and `mapT`). For each position `i`, store the last index `i+1` where each character was seen. If at any position the two arrays disagree, the mapping is not isomorphic.

Storing `i+1` (instead of `i`) so that 0 means "never seen" — avoids the index-0 ambiguity.

**Optimized Java Solution:**
```java
public static boolean isIsomorphic(String s, String t) {
    if (s.length() != t.length()) return false;
    int[] mapS = new int[256], mapT = new int[256];
    for (int i = 0; i < s.length(); i++) {
        if (mapS[s.charAt(i)] != mapT[t.charAt(i)]) return false;
        mapS[s.charAt(i)] = i + 1;
        mapT[t.charAt(i)] = i + 1;
    }
    return true;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Using only ONE map (one-way mapping check passes false cases)
- Storing `i` instead of `i+1` (zero collision with default)
- Forgetting the length-equality short-circuit

**Follow-up Tricky Questions:**
- Word pattern problem (`"abba"` matches `"dog cat cat dog"`)
- Find all words in a list that match the same pattern
- Is one string a "scrambled" version of another?

public static boolean isHappy(int n) {

}

public static int fourSumCount(int[] A, int[] B, int[] C, int[] D) {

### Q40. Maximum Sum Subarray of Size K (Fixed Window)

**Difficulty:** Easy-Medium

**Asked In:**
- Wipro
- Accenture
- Wells Fargo
- Startups
- TCS

**Interviewer Expectation:**
The foundational fixed-window problem. They want to see clean window-slide logic — no recomputing the sum from scratch each time.

**Optimized Explanation:**
Compute the sum of the first K elements. Then "slide" the window one step at a time: add the new right element, subtract the leaving left element. Track the max sum seen.

**Optimized Java Solution:**
```java
public static int maxSumWindowK(int[] arr, int k) {
    int sum = 0;
    for (int i = 0; i < k; i++) sum += arr[i];
    int best = sum;
    for (int i = k; i < arr.length; i++) {
        sum += arr[i] - arr[i - k];
        best = Math.max(best, sum);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Recomputing the sum from scratch each window (O(n*k) trap)
- Off-by-one when initializing the first window
- Not handling `k > arr.length`

**Follow-up Tricky Questions:**

### Q41. Longest Substring with At Most K Distinct Characters

**Difficulty:** Medium-Hard

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
The template for "at most K of something" variable window problems. They want you to remember the shrink condition and not let the HashMap blow up.

**Optimized Explanation:**
Expand `right`, maintaining a frequency map. When the map size exceeds K (too many distinct chars), shrink from the left until the invariant holds again. Track the maximum window size.

**Optimized Java Solution:**
```java
public static int longestSubstringKDistinct(String s, int k) {
    Map<Character, Integer> map = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        map.merge(s.charAt(right), 1, Integer::sum);
        while (map.size() > k) {
            char lc = s.charAt(left++);
            if (map.merge(lc, -1, Integer::sum) == 0) map.remove(lc);
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(k)

**Common Mistakes:**
- Forgetting to remove the key when count drops to zero (map.size grows incorrectly)
- Confusing "at most K" with "exactly K"
- Not handling k = 0

**Follow-up Tricky Questions:**
- "Exactly K distinct" = "at most K" - "at most K-1"
- Replace characters in window — Longest Repeating Char Replacement

### Q42. Minimum Window Substring

**Difficulty:** Hard (Medium-Hard for our cap)

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
The hardest sliding window pattern that still appears at 3-yr level — but only at product companies and Wells Fargo. They want a `have/need` counter to avoid recomputing.

**Optimized Explanation:**
You're looking for the shortest window in `s` that contains all characters of `t` (with frequencies). Maintain a `need` array of required counts. Expand right — when a required char appears (count was > 0), decrement `required`. When `required == 0`, try shrinking from the left while still keeping the window valid. Track the minimum window each time.

**Optimized Java Solution:**
```java
public static String minWindow(String s, String t) {
    if (s.length() < t.length()) return "";
    int[] need = new int[256];
    for (char c : t.toCharArray()) need[c]++;
    int required = t.length(), left = 0, bestLen = Integer.MAX_VALUE, bestL = 0;
    for (int right = 0; right < s.length(); right++) {
        if (need[s.charAt(right)]-- > 0) required--;
        while (required == 0) {
            if (right - left + 1 < bestLen) {
                bestLen = right - left + 1; bestL = left;
            }
            if (++need[s.charAt(left++)] > 0) required++;
        }
    }
    return bestLen == Integer.MAX_VALUE ? "" : s.substring(bestL, bestL + bestLen);
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1) (fixed alphabet)

**Common Mistakes:**
- Mixing up the post-increment/decrement timing in the conditions
- Forgetting that surplus chars are negative in `need[]`
- Not handling the "no valid window" case

**Follow-up Tricky Questions:**
- Return the substring with all distinct chars (different problem)
- All occurrences of valid windows
- Minimum window covering all distinct chars in `s` itself?

### Q43. Find All Anagrams in a String

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
A clean fixed-size sliding window problem with frequency comparison. They want you to slide the window and use `Arrays.equals` to compare frequency arrays — not recompute from scratch.

**Optimized Explanation:**
Build the frequency array of `p`. Slide a window of size `p.length()` across `s`. At each step, add the rightmost char to the window's frequency, remove the leftmost char (when window is full). When the two frequency arrays match, you've found an anagram — record the start index.

**Optimized Java Solution:**
```java
public static List<Integer> findAnagrams(String s, String p) {
    List<Integer> res = new ArrayList<>();
    if (s.length() < p.length()) return res;
    int[] pf = new int[26], sf = new int[26];
    for (char c : p.toCharArray()) pf[c - 'a']++;
    for (int i = 0; i < s.length(); i++) {
        sf[s.charAt(i) - 'a']++;
        if (i >= p.length()) sf[s.charAt(i - p.length()) - 'a']--;
        if (Arrays.equals(pf, sf)) res.add(i - p.length() + 1);
    }
    return res;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Recomputing the frequency from scratch each iteration (O(n*k))
- Off-by-one in the starting-index computation
- Forgetting the length-check guard

**Follow-up Tricky Questions:**
- Return only the count of anagrams

- Permutation in String (boolean version of this)

### Q44. Longest Repeating Character Replacement

**Difficulty:** Medium-Hard

**Asked In:**
- IBM
- Deloitte
- Startups
- Amazon

**Interviewer Expectation:**
The clever invariant: `windowLength - maxFreqChar <= k`. If you replace at most k chars in the window, you need `windowSize - mostFrequent <= k`. They are checking if you spot this invariant.

**Optimized Explanation:**
Track the frequency of each char in the window. Keep updating `maxFreq` (frequency of most common char). If `windowSize - maxFreq > k`, the window can't be made uniform with k replacements — shrink left. The window never shrinks more than needed because we always track the max we've seen.

**Optimized Java Solution:**
```java
public static int characterReplacement(String s, int k) {
    int[] freq = new int[26];
    int left = 0, maxFreq = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        maxFreq = Math.max(maxFreq, ++freq[s.charAt(right) - 'A']);
        if (right - left + 1 - maxFreq > k) freq[s.charAt(left++) - 'A']--;
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Recomputing `maxFreq` after every shrink (not needed, window only grows or stays same)
- Wrong direction for the shrink condition
- Using lowercase offset on uppercase string

**Follow-up Tricky Questions:**
- Same problem but with lowercase strings
- At most K distinct characters (different problem, similar template)
- Track which character "won" the window

Two pointers — `l` from the left, `r` from the right. Compute sum. If too small, advance `l`. If too big, decrement `r`. If equal, return. This works because of sorting — moving inward predictably increases or decreases the sum.

**Optimized Java Solution:**

public static int[] pairSumSorted(int[] arr, int target) {

        if (sum == target) return new int[]{l, r};
        else if (sum < target) l++;
        else r--;
    }
    return new int[]{-1, -1};
}

### Q48. Three Sum

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe
- Flipkart

**Interviewer Expectation:**
The "skip duplicates" requirement is the trap. They will test it with arrays containing duplicates and watch for duplicate triplets in your output.

**Optimized Explanation:**
Sort the array. Fix one element with a loop, then use two pointers on the rest of the array — the classic pair-sum on sorted subarray. Skip duplicates at THREE places: the outer fix, the left pointer after a match, and the right pointer after a match.

**Optimized Java Solution:**
```java
public static List<List<Integer>> threeSum(int[] arr) {
    Arrays.sort(arr);
    List<List<Integer>> res = new ArrayList<>();
    for (int i = 0; i < arr.length - 2; i++) {
        if (i > 0 && arr[i] == arr[i - 1]) continue;
        int l = i + 1, r = arr.length - 1;
        while (l < r) {
            int sum = arr[i] + arr[l] + arr[r];
            if (sum == 0) {
                res.add(Arrays.asList(arr[i], arr[l], arr[r]));
                while (l < r && arr[l] == arr[l + 1]) l++;
                while (l < r && arr[r] == arr[r - 1]) r--;
                l++; r--;
            } else if (sum < 0) l++;
            else r--;
        }
    }
    return res;
}
```

**Time Complexity:** O(n²)

**Space Complexity:** O(1) extra (not counting output)

**Common Mistakes:**
- Forgetting to skip duplicates on any of the three pointers
- Not sorting first (two-pointer breaks)
- Using HashSet of triplets to dedupe (works but wasteful)

**Follow-up Tricky Questions:**
- Three Sum Closest (closest sum to target)

### Q49. Container With Most Water

**Difficulty:** Medium

**Asked In:**
- Wells Fargo

- Amazon
- Adobe

**Interviewer Expectation:**

**Optimized Explanation:**
Two pointers at both ends. Area = `width × min(left, right)`. To increase the area, you must increase either the width or the min height — but width only decreases as you move inward, so the only hope is to increase the min height. That means moving the *shorter* side inward (moving the taller side cannot improve the min).

**Optimized Java Solution:**
```java
public static int maxArea(int[] height) {
    int l = 0, r = height.length - 1, best = 0;
    while (l < r) {
        int h = Math.min(height[l], height[r]);
        best = Math.max(best, h * (r - l));
        if (height[l] < height[r]) l++; else r--;
    }
    return best;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Moving the taller side (greedy choice is wrong)
- Trying all pairs O(n²) — TLE on large inputs
- Computing width as `r - l + 1` (it's `r - l` — water is BETWEEN the lines)

### Q50. Trapping Rain Water

**Difficulty:** Medium-Hard

**Asked In:**
- Wells Fargo

- Walmart
- Product companies

**Interviewer Expectation:**
The two-pointer O(1)-space solution is the gold answer. The prefix-max/suffix-max O(n)-space version is the warm-up. They want both.

**Optimized Explanation:**
At any index, the water trapped = `min(maxLeft, maxRight) - height[i]`. Two pointers from both ends — keep `lm` (max from left) and `rm` (max from right). Whichever side has the smaller bar determines how much water is trapped there, because the smaller side bounds the water height.

**Optimized Java Solution:**
```java
public static int trapRainWater(int[] h) {
    int l = 0, r = h.length - 1, lm = 0, rm = 0, total = 0;
    while (l < r) {
        if (h[l] < h[r]) {
            if (h[l] >= lm) lm = h[l]; else total += lm - h[l];
            l++;
        } else {
            if (h[r] >= rm) rm = h[r]; else total += rm - h[r];
            r--;
        }
    }
    return total;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(1)

**Common Mistakes:**
- Moving both pointers without considering which side bounds water

### Q51. Squares of a Sorted Array

**Optimized Java Solution:**

public static int[] sortedSquares(int[] arr) {
    int n = arr.length, l = 0, r = n - 1, k = n - 1;

    while (l <= r) {

        if (ls > rs) { res[k--] = ls; l++; }
        else         { res[k--] = rs; r--; }

    return res;
}

### Q53. Reverse Vowels in a String

**Difficulty:** Easy

**Interviewer Expectation:**

**Optimized Explanation:**

**Optimized Java Solution:**
```java
public static String reverseVowels(String s) {
    char[] c = s.toCharArray();
    int l = 0, r = c.length - 1;
    String vowels = "aeiouAEIOU";
    while (l < r) {
        while (l < r && vowels.indexOf(c[l]) < 0) l++;
        while (l < r && vowels.indexOf(c[r]) < 0) r--;
        char t = c[l]; c[l++] = c[r]; c[r--] = t;
    }
    return new String(c);
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n) (char array for String)

**Common Mistakes:**
- Using `String` and concatenation (slow + immutable)
- Forgetting to handle uppercase vowels
- Wrong loop guards — `l < r` must be checked in inner loops too

**Follow-up Tricky Questions:**
- Reverse only consonants
- Reverse only digits in a string
- Reverse only the substring matching a predicate

### Q54. Next Greater Element

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
The monotonic stack pattern — once you see it, you'll see it everywhere (Daily Temperatures, Stock Span, etc.). They want O(n) with a single stack pass.

**Optimized Explanation:**
Maintain a stack of indices whose "next greater" hasn't been resolved yet. Walk the array. For each index `i`, pop the stack while the top's value is less than `arr[i]` — for each popped index, `arr[i]` is its next greater. Then push `i`.

**Optimized Java Solution:**
```java
public static int[] nextGreaterElement(int[] arr) {
    int n = arr.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> st = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!st.isEmpty() && arr[st.peek()] < arr[i])
            res[st.pop()] = arr[i];
        st.push(i);
    }
    return res;
}
```

**Time Complexity:** O(n) — each index is pushed and popped at most once

**Space Complexity:** O(n)

**Common Mistakes:**
- Storing values instead of indices (you lose the position to write to)
- Using brute O(n²) nested loop — TLE
- Wrong stack direction (must be decreasing from bottom to top)

**Follow-up Tricky Questions:**
- Next Greater Element II (circular array)
- Previous Greater Element (mirror — iterate from the back)
- Next Smaller Element (flip comparison)

### Q55. Implement Queue Using Two Stacks

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Wipro
- Accenture
- Wells Fargo
- Startups
- Infosys

**Interviewer Expectation:**
The amortized O(1) pattern. They want to see you understand WHY moving elements only when `out` is empty gives amortized O(1) — not O(n) per dequeue.

**Optimized Explanation:**
Two stacks — `in` and `out`. Enqueue → push to `in`. Dequeue → if `out` is empty, drain all of `in` into `out` (reversing the order), then pop from `out`. Each element is moved at most twice, so amortized O(1).

**Optimized Java Solution:**
```java
public static class MyQueue {
    private final Deque<Integer> in  = new ArrayDeque<>();
    private final Deque<Integer> out = new ArrayDeque<>();
    public void enqueue(int x) { in.push(x); }
    public int dequeue() {
        if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());
        return out.pop();
    }
    public int peek() {
        if (out.isEmpty()) while (!in.isEmpty()) out.push(in.pop());
        return out.peek();
    }
    public boolean isEmpty() { return in.isEmpty() && out.isEmpty(); }
}
```

**Time Complexity:** O(1) amortized per operation

**Space Complexity:** O(n)

**Common Mistakes:**
- Moving elements on EVERY dequeue (becomes O(n))
- Using the legacy `Stack` class
- Forgetting to check both stacks for `isEmpty`

**Follow-up Tricky Questions:**
- Implement Stack using Two Queues (mirror problem)
- Implement Queue using ONE stack (use recursion — interesting trick)
- Generic version with type parameters

### Q56. Implement Stack Using Two Queues

**Difficulty:** Easy-Medium

**Asked In:**
- TCS
- Wipro
- Accenture
- Startups

**Interviewer Expectation:**
The trick: rotate the queue on push so the latest element ends up at the front. Push becomes O(n), but pop/top are O(1).

**Optimized Explanation:**
Maintain a queue. On `push`, offer the element, then rotate the queue by moving every previous element to the back. The new element is now at the front, so pop/top are O(1).

**Optimized Java Solution:**
```java
public static class MyStack {
    private final Deque<Integer> q = new ArrayDeque<>();
    public void push(int x) {
        q.offer(x);
        int n = q.size();
        while (n-- > 1) q.offer(q.poll());
    }
    public int pop()  { return q.poll(); }
    public int top()  { return q.peek(); }
    public boolean empty() { return q.isEmpty(); }
}
```

**Time Complexity:** push O(n), pop/top O(1)

**Space Complexity:** O(n)

**Common Mistakes:**
- Using two queues but doing the work twice
- Confusing `offer/poll/peek` with `push/pop/peek`
- Off-by-one in the rotation count

**Follow-up Tricky Questions:**
- Make pop O(n) and push O(1) instead (mirror)
- Generic implementation with type parameter
- Get the minimum element in O(1) — that's Min Stack

### Q57. Min Stack

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
A classic OOP design problem. They want O(1) for ALL operations including `getMin`. The parallel-min-stack trick is the standard solution.

**Optimized Explanation:**
Maintain two stacks — one for actual values, one parallel "min stack" tracking the minimum at each level. Only push to min-stack when the new value is ≤ current min. On pop, if the popped value equals current min, pop min-stack too.

**Optimized Java Solution:**
```java
public static class MinStack {
    private final Deque<Integer> stack    = new ArrayDeque<>();
    private final Deque<Integer> minStack = new ArrayDeque<>();
    public void push(int x) {
        stack.push(x);
        if (minStack.isEmpty() || x <= minStack.peek()) minStack.push(x);
    }
    public void pop() {
        int v = stack.pop();
        if (v == minStack.peek()) minStack.pop();
    }
    public int top()    { return stack.peek(); }
    public int getMin() { return minStack.peek(); }
}
```

**Time Complexity:** O(1) per operation

**Space Complexity:** O(n)

**Common Mistakes:**
- Using `<` instead of `<=` when pushing to min-stack (breaks on duplicates)
- Not popping min-stack when the top value matches
- Storing pairs `(value, currentMin)` in a single stack — works but uses more memory

**Follow-up Tricky Questions:**
- Max Stack (mirror)
- Min Queue (harder — uses monotonic deque)
- Implement with O(1) space overhead (encoding trick with two ints)

### Q58. Daily Temperatures

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
A variation of Next Greater Element — they want the same monotonic-stack pattern but with index-difference output. Direct knowledge transfer.

**Optimized Explanation:**
Monotonic stack of indices (decreasing temperatures). For each day, while the stack top's temperature is colder than today's, pop and record `today's index - popped index` as the "days to wait."

**Optimized Java Solution:**
```java
public static int[] dailyTemperatures(int[] t) {
    int n = t.length;
    int[] res = new int[n];
    Deque<Integer> st = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        while (!st.isEmpty() && t[st.peek()] < t[i]) {
            int idx = st.pop();
            res[idx] = i - idx;
        }
        st.push(i);
    }
    return res;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Storing temperatures instead of indices on the stack
- Using brute O(n²) nested loops
- Forgetting to leave 0 (default) for days with no warmer future

**Follow-up Tricky Questions:**
- How many days before a colder day? (mirror — iterate from back)
- Stock Span Problem (similar but counts previous greater-or-equal days)
- Sliding Window Max (more advanced variant)

### Q59. Evaluate Reverse Polish Notation

**Difficulty:** Medium

**Asked In:**
- Wells Fargo
- Startups
- Amazon
- Adobe

**Interviewer Expectation:**
A classic stack problem. They will test you on the operand order for `-` and `/` — the second-popped value is the first operand.

**Optimized Explanation:**
Walk through the tokens. If it's a number, push. If it's an operator, pop two values — `b` first, then `a` — and compute `a OP b`. Push the result back. After the loop, the single remaining value on the stack is the answer.

**Optimized Java Solution:**
```java
public static int evalRPN(String[] tokens) {
    Deque<Integer> st = new ArrayDeque<>();
    for (String tok : tokens) {
        switch (tok) {
            case "+": case "-": case "*": case "/":
                int b = st.pop(), a = st.pop();
                switch (tok) {
                    case "+": st.push(a + b); break;
                    case "-": st.push(a - b); break;
                    case "*": st.push(a * b); break;
                    case "/": st.push(a / b); break;
                }
                break;
            default:
                st.push(Integer.parseInt(tok));
        }
    }
    return st.pop();
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(n)

**Common Mistakes:**
- Order of operands for `-` and `/` flipped (computing `b - a` instead of `a - b`)
- Forgetting that single negative numbers like `"-3"` are valid tokens
- Using string comparison with `==` instead of `.equals()` (works for switch-on-String though)

**Follow-up Tricky Questions:**
- Convert infix expression to RPN, then evaluate
- Support unary minus and exponentiation
- Validate the expression before evaluating

### Q60. Sliding Window Maximum

**Difficulty:** Medium-Hard

**Asked In:**
- Wells Fargo
- Amazon
- Adobe
- Walmart
- Mid-stage startups
- Mid-tier product companies

**Interviewer Expectation:**
The interviewer wants:
- Sliding window understanding
- Deque optimization (monotonic deque)
- Ability to reduce brute force O(n*k) to O(n)
- Edge case handling (window boundaries)

**Optimized Explanation:**
Maintain a monotonic decreasing deque of *indices*. The front always holds the index of the current window's maximum. For every new element:
1. Remove indices that fall outside the current window (front)
2. Remove indices from the back whose values are ≤ current value (they can never be the max anymore)
3. Add current index at the back
4. Once the window is full (`i >= k - 1`), record `arr[front]` as the window's max

**Optimized Java Solution:**
```java
public static int[] maxSlidingWindow(int[] arr, int k) {
    int n = arr.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();
    for (int i = 0; i < n; i++) {
        if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();
        while (!dq.isEmpty() && arr[dq.peekLast()] <= arr[i]) dq.pollLast();
        dq.offerLast(i);
        if (i >= k - 1) res[i - k + 1] = arr[dq.peekFirst()];
    }
    return res;
}
```

**Time Complexity:** O(n)

**Space Complexity:** O(k)

**Common Mistakes:**
- Storing values instead of indices (you need indices for window-bound checks)
- Forgetting window boundary removal at the front
- Incorrect deque order — must be monotonically decreasing
- Comparing using `<` vs `<=` incorrectly

**Follow-up Tricky Questions:**
- How would you solve this using a PriorityQueue? (O(n log n))
- Why is the deque better than a heap here?
- What changes for the *minimum* in each window?
- Can this work for streaming data?

## Java-Specific Pitfalls

- Use `StringBuilder` inside loops, not `String +=`
- For char-to-index: `(c - 'a')` for lowercase, `(c - 'A')` for uppercase
- `HashMap.get(key)` returns null — use `getOrDefault` or `containsKey` first
- Integer overflow: when summing arrays, prefer `long` for safety
- For stack: use `Deque<Integer>` with `ArrayDeque` — never the legacy `Stack` class
- For queue: `ArrayDeque` or `LinkedList`
- `HashMap` iteration order is not guaranteed — use `LinkedHashMap` if order matters
- `Arrays.asList(int[])` does NOT box — use `IntStream.of(...).boxed().toList()`
- `Arrays.sort(int[])` uses dual-pivot quicksort — NOT stable
- `Collections.sort(List<T>)` uses Timsort — stable
