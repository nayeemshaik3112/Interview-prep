## What is Spring Boot auto-configuration? How does it work?
Spring Boot's @EnableAutoConfiguration scans the classpath using conditions (@ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty) to automatically configure Spring beans based on what's available.
For example, if HikariDataSource is on the classpath and you've provided spring.datasource.url, it auto-configures a DataSource bean. You can override any auto-configured bean by defining your own @Bean — the @ConditionalOnMissingBean condition ensures the auto-config steps back when you define your own
-------------------------------------------------------
## What is @SpringBootApplication? What three annotations does it combine?

@SpringBootApplication combines: 
(1) @Configuration — marks the class as a source of @Bean definitions
(2) @EnableAutoConfiguration — enables Spring Boot's auto-configuration mechanism
(3) @ComponentScan — scans the current package and sub-packages for Spring components (@Service, @Repository, @Controller, etc.).
-------------------------------------------------------

## Your claims-service has spring.config.import: optional:configserver:.... What does optional: means
The optional: prefix means: if the Config Server is unreachable, the service will still start using its local application.yml values instead of failing. Without optional:, if the Config Server is down, the service refuses to start entirely.

In my IVR project, auto-configuration does heavy lifting.
The claims-service just adds spring-boot-starter-data-jpa to pom.xml, and Spring Boot auto-configures Hibernate, HikariCP connection pool, and JPA repositories. 
Similarly, adding spring-kafka auto-configures KafkaTemplate and consumer factories. 
I override only what I need — for example, I define a custom KafkaTopicConfig bean for the claim-events topic with 3 partitions — because the auto-configured defaults don't match my requirements

## What is a circular dependency

Circular dependency is when Bean A depends on Bean B and Bean B depends on Bean A. 
With constructor injection, Spring cannot resolve this and throws BeanCurrentlyInCreationException at startup. This is actually good — it forces you to fix a design problem (two services that depend on each other likely have a design flaw). 

class A(){
   public A(B b){}
}
class B(){
   public B(A a){}
} // this is bad

class A {
    private B b;

    @Autowired
    public void setB(B b) {
        this.b = b;
    }
}

## What is the difference between @Primary and @Qualifier?
@Primary marks one bean as the default when there's ambiguity — it's a class-level declaration. @Qualifier is used at the injection point to explicitly name which bean to use. If @Qualifier is present, it overrides @Primary. Think of @Primary as the default choice and @Qualifier as an explicit override.
