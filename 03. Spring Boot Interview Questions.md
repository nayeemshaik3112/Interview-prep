## What is Spring Boot auto-configuration? How does it work?
Spring Boot's @EnableAutoConfiguration scans the classpath using conditions (@ConditionalOnClass, @ConditionalOnMissingBean, @ConditionalOnProperty) to automatically configure Spring beans based on what's available.
For example, if HikariDataSource is on the classpath and you've provided spring.datasource.url, it auto-configures a DataSource bean. You can override any auto-configured bean by defining your own @Bean — the @ConditionalOnMissingBean condition ensures the auto-config steps back when you define your own
-------------------------------------------------------
## What is @SpringBootApplication? What three annotations does it combine?

@SpringBootApplication combines: 
(1) @Configuration — marks the class as a source of @Bean definitions
(2) @EnableAutoConfiguration — enables Spring Boot's auto-configuration mechanism
(3) @ComponentScan — scans the current package and sub-packages for Spring components (@Service, @Repository, @Controller, etc.).

## Your claims-service has spring.config.import: optional:configserver:.... What does optional: means
The optional: prefix means: if the Config Server is unreachable, the service will still start using its local application.yml values instead of failing. Without optional:, if the Config Server is down, the service refuses to start entirely.

## What is a circular dependency

Circular dependency is when Bean A depends on Bean B and Bean B depends on Bean A. 
With constructor injection, Spring cannot resolve this and throws BeanCurrentlyInCreationException at startup. This is actually good — it forces you to fix a design problem (two services that depend on each other likely have a design flaw). 

class A(){
   public A(B b){}
}
class B(){
   public B(A a){}
} // this is bad

class A {
    private B b;

    @Autowired
    public void setB(B b) {
        this.b = b;
    }
}

## What is the difference between @Primary and @Qualifier?
@Primary marks one bean as the default when there's ambiguity — it's a class-level declaration. @Qualifier is used at the injection point to explicitly name which bean to use. If @Qualifier is present, it overrides @Primary. Think of @Primary as the default choice and @Qualifier as an explicit override.

## What is @postconstruct
@PostConstruct is used to execute initialization logic after dependency injection is complete. It ensures that all required beans are available before performing tasks like validation, cache loading, or resource initialization. It is preferred over constructors for such logic because dependencies are fully injected at this stage.

## Create a controller this or simple one
@RestController
@RequestMapping("/api/v1/claims")
@RequiredArgsConstructor  // Lombok — generates constructor for final fields
public class ClaimCommandController {

    private final CommandGateway commandGateway;

    @PostMapping
    public ResponseEntity<Map<String, String>> createClaim(
            @RequestBody @Valid ClaimRequest request) {
        String claimId = UUID.randomUUID().toString();
        commandGateway.sendAndWait(new CreateClaimCommand(
                claimId,
                request.customerId(),
                request.policyNumber(),
                request.description()
        ));
        return ResponseEntity
                .status(HttpStatus.CREATED)
                .body(Map.of("claimId", claimId));
    }

    @PatchMapping("/{claimId}/status")
    public ResponseEntity<Void> updateStatus(
            @PathVariable String claimId,
            @RequestBody @Valid ClaimStatusUpdateRequest request) {
        commandGateway.sendAndWait(
                new UpdateClaimStatusCommand(claimId, request.status())
        );
        return ResponseEntity.ok().build();
    }
}

What is the difference between @ExceptionHandler in a controller vs in @ControllerAdvice?" → Inside a controller, @ExceptionHandler only handles exceptions from that controller. In @RestControllerAdvice (which is @ControllerAdvice + @ResponseBody), it handles exceptions from ALL controllers globally.

"How do you version a REST API?" → 
API versioning is used to manage changes without breaking existing clients. The most common approach is URL versioning like /api/v1/claims. Other methods include header-based versioning and query parameter versioning, but URL versioning is preferred due to its simplicity and visibility.

## What is the difference between Filter and Interceptor?
Filter operates at the Servlet container level — before Spring MVC processes the request. It has access only to raw HttpServletRequest and HttpServletResponse. Interceptor operates inside the Spring MVC DispatcherServlet — it has access to the HandlerMethod (knows which controller and method will handle the request). Use Filter for authentication, CORS, and encoding (because they run before Spring even sees the request). Use Interceptor for audit logging and business-specific logic that needs to know which handler is being invoked.

 ## Is @Transactional implemented using AOP?
@Transactional works using Spring AOP proxies. The proxy starts and manages the transaction around the method. However, if a transactional method is called from within the same class, the proxy is bypassed, so the transaction does not work.

@Service
public class OrderService {

    @Transactional
    public void methodA() {
        methodB();  // ❌ problem
    }

    @Transactional
    public void methodB() {
        // DB logic
    }
}

## What is the difference between @Value and @ConfigurationProperties?
@Value("${server.port}")
private int port;

@Value is used to inject individual property values, while @ConfigurationProperties is used to bind a group of related properties into a strongly typed class. For production applications with multiple configuration values, @ConfigurationProperties is preferred because it is type-safe and more maintainable.
