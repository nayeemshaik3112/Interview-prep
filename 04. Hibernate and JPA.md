22. Eager vs Lazy fetching
    Eager fetching loads related data immediately, while lazy fetching loads it only when accessed, improving performance.

23. get() vs load() methods in Hibernate
    call get() → DB hit → returns real object
    call load() → returns proxy → access field → DB hit

get() immediately fetches data from the database and returns null if not found, while load() returns a proxy object and fetches data lazily, throwing an exception if the entity does not exist.

## What is the difference between JPA and Hibernate?
JPA is a standard/specification; Hibernate is a JPA provider (implementation). JPA defines interfaces and annotations; Hibernate provides the actual ORM behavior and SQL generation. Spring Data JPA usually uses Hibernate under the hood, but you code to JPA APIs.

## CrudRepository vs JpaRepository?
CrudRepository provides basic CRUD operations. JpaRepository extends it and adds JPA-specific features like pagination 

@Entity
public class Customer {
    @Id
    @GeneratedValue
    private Long id;

    private String name;

    @OneToMany(mappedBy = "customer", fetch = FetchType.LAZY, cascade = CascadeType.ALL)
    private List<Order> orders = new ArrayList<>();
}

@Entity
public class Order {
    @Id
    @GeneratedValue
    private Long id;

    private Double amount;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "customer_id", nullable = false)
    private Customer customer;
}

## N+1 Query Problem (interview favorite)
Definition (how you should say it):

N+1 occurs when you fetch a list of entities with one query, then for each entity you lazily load a related association with another query — resulting in 1 (for parent list) + N (for each child) queries instead of 1 properly joined query.

List<Customer> customers = customerRepository.findAll();  // 1 query
for (Customer c : customers) {
    System.out.println(c.getOrders().size());            // N queries (one per customer)
}   

Use JPQL with JOIN FETCH:
@Query("select c from Customer c join fetch c.orders")
List<Customer> findAllWithOrders();

## LAZY vs EAGER? Which do you prefer?

LAZY loads the association only when it’s accessed; EAGER loads it immediately with the parent entity. In microservices, LAZY is safer for most associations because EAGER can lead to large, unexpected object graphs being loaded, performance issues, and N+1 if you have nested EAGER relationships. I prefer LAZY by default and explicitly fetch associations with JOIN FETCH or @EntityGraph only when needed.

## Transactions & @Transactional

A transaction ensures that a group of database operations either all succeed or all fail. In Spring, @Transactional is used to manage transactions declaratively. It starts a transaction before method execution and commits or rolls back based on success or exception.

@Service
public class PaymentService {

    @Transactional
    public void transfer() {
        deductMoney();
        addMoney();
    }
}
Start Transaction
   ↓
Run method
   ↓
If success → COMMIT ✅
If exception → ROLLBACK ❌
--------------------------------------------------------------------------------
## Why put @Transactional on service methods, not repository interfaces?

Service layer defines the business operation boundary. A single business use case often involves multiple repository calls (e.g., create claim + write outbox + update some other table). @Transactional at service keeps the whole operation atomic. If you put it at repository level only, each repo call is its own transaction and you lose atomicity across them.
